Branch `20261122-core_utils`, PR #841, cut from origin/main. Proved: `pnpm --filter safebyok lint`, `typecheck`, `test` (30 files, 1392 tests, 6 of them new in `tests/utils.test.ts`) and `build` green, attw and publint clean.

* **Built**: the `safebyok/utils` entry, `packages/safebyok/src/utils.ts`, with `./utils` in `exports`, `publishConfig.exports` and `typesVersions` (spelt as `./storage` is), `src/utils.ts` in the tsdown entry list, and `tests/utils.test.ts`. Names, as big's `utils.ts` exports them: `MaskSchedule`, `mask`, `fromB64`, `toB64`, `WhisperFieldAttributes`, `mash`, and the types `MaskOpts` and `MaskRow`. A changeset, empty-frontmatter with a sentence, as the other private-core threads write theirs.
* **Decisions made**: every name is a plain re-export from `safebyok-big/utils`, big's own `utils` entry, the one the front door `safebyok` already re-exports `mask`, `mash` and the codec from. Nothing is newly exported from `safebyok-big/internals`, and big's code is untouched. The brief proposed internals for names missing there (`mask`, `MaskSchedule`, `WhisperFieldAttributes`, `MaskOpts`, `MaskRow`, and `mash`, which `internals` does not carry; only `Crypto.toB64`/`fromB64` it does). The reason it went the other way: `safebyok-big/utils` is already a published-shaped entry carrying exactly these names and no vault, whereas `safebyok-big/internals` is `export * as ...` over the whole vault, so pulling these names through it would have made `dist/utils.js` drag the vault in and broken the module's promise. Re-exporting at the entry also keeps one binding per name across both packages.
* **`dist/utils.js` imports**: one line, `export { ... } from "safebyok-big/utils"`, and `dist/utils.cjs` one `require("safebyok-big/utils")`. No file of the new core's vault is reached.
* **Test**: the export list, equality of each value with big's, and one behaviour each (`mash('abc')` known value, a `toB64`/`fromB64` round trip, a `mask` call, `MaskSchedule` frozen, a `WhisperFieldAttributes` flag). Big's own suite (mash edge cases, refusal of non-strings, mask schedule rows) is not ported: those behaviours are big's, tested there.
* **Deviations**: the route above, not internals. Not added to `scripts/front-door.ts`'s check in the build (`. ./core ./storage`): the front door carries all but `MaskSchedule` and the type `MaskRow` of these names, so the check would report `MaskSchedule` missing; it was not asked for and the front door is not changed.
* **Discoveries**: `index.ts` already re-exports `WhisperFieldAttributes, fromB64, mask, mash, toB64, type MaskOpts` from `safebyok-big/utils`; `MaskRow` and `MaskSchedule` are new to the new core's surface through this entry; the front door lacks both.
