# Thread: type aliases in the lean core (2026-11-17)

Branch `20261117-type_aliases_lean`, outside any sprint, stacked on nothing (cut from origin/main 193708df9). Proved: `pnpm --filter safebyok` lint, typecheck, test (15 files, 871 tests) green; `pnpm justify` below.

* **Built**: `packages/safebyok/src/storage/primitives.ts`, the one home for nine plain aliases, each with a one-line doc block: `Userid`, `Banklabel`, `Labelpath`, `Lifeseq`, `Lifepath`, `Lifenum`, `Revtok`, `DeviceTok` (all `string` or `number`) and `EpochMillis` (= big's `CX.EpochMillis`, a `number`). Exported from `src/index.ts`, `core.ts` and `storage.ts`. Used in the hand-written signatures, props, type literals and `Map` keys of `models/` (base-thing, lease, device, gating, wayin, bank, sealers), `minding/thing-minder.ts` and `storage/` (shapes-thing, thing-classifier, memory-vault-db), and in the test helpers' signatures. Types only: no runtime change, no renamed field or variable.
* **Decisions made**:
  - Defined here rather than re-exported from big: a plain alias is structural, so a copy splits nothing (unlike a class), and big's names differ (`UserID` for `user_id`; the new core's field is `userid`). `EpochMillis` is the exception: big already names it, so it aliases `CX.EpochMillis`.
  - Not aliased where the literal type matters: `ShellLifeseq`, `ShellLifepath`, `MainGateLabelpath` and `RootBoxLabelpath` stay unannotated consts, so that `lit(ShellLifeseq)` keeps its literal.
  - Types a validator infers (`ThingScope`, `ThingRecord`, `Track`, and so on) are untouched.
* **Rejected candidates**: `Revseq` (two hand-written sites, one file group); `Boxlabel`/`Gatelabel` (one site, `BaseThing.label`, which holds any thing's last label); `Gatingtok` (one prop); `Oplabel` (three overloads in one file); a duration alias for `leaseMillis`, `staleTime`, `gcTime` (three unrelated settings, no shared meaning); `PassphraseCleartext` for `judgeStrength`'s parameter (it would narrow what the method accepts); the ckey `Map<string, ...>` of banks in `MemoryVaultDB` (a ckey is not a userid or banklabel).
* **`as const satisfies`**: all the tables in `src/` already had it (`ThingFormats`, `MaxLabelsUnder`, `KindChecks`, `GatePolicies`, `PurposeForWayinkind`, `VaultDBMembernames`, `thingkindVals`). Added in tests/models/lease.test.ts: `StampFieldnames` (`readonly (keyof LeaseRecord)[]`) and `SealerMembernames` (`readonly (keyof Sealer<BoxThing, BoxCleartexts>)[]`). Left: `gatingkindVals = ['birth_bank'] as const` in `models/gating.ts`: `birth_bank` is the lean core's own kind and is not in big's `EX.Gatingkind`, so `satisfies` refuses it.
* **Deviations**: `tests/test-helpers/models-world.ts` keeps `device_tok?: string`: the file already exports a value named `DeviceTok`, which the type's name would merge with.
* **Discoveries**: the changeset is empty, as for the other lean-core threads (`safebyok` is private); its body says what a host sees.
* **For the Coach**: nothing blocking. Exports: the nine aliases, from all three entry points.
