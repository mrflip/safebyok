# Thread 12: provider_owns (2026-11-22)

Branch `20261122-provider_owns`, PR (draft) stacked on #826. Proved: `pnpm --filter safebyok-react-lean test` (23 files, 304 tests), `tsc --noEmit` and `eslint src tests` clean in the package; `pnpm justify` at the tip before `ready`.

The brief's "holder" is `ProviderMount` in the code (`hold` is a word VOCABULARY.md asks us to avoid).

* **Built** (all in `packages/safebyok-react-lean`):
  * **`ProviderMount`** (`react-giver.tsx`, [Types] and [The giver]): `{ client, device }`, made once per mount of the Provider in a `useState` lazy initializer (`makeProviderMount`): `client` is `ThingMinder.makeClient()`, `device` null. No I/O, no global, no subscription, so a server render and StrictMode's discarded twin are harmless.
  * **The device from an effect on `userid`**: `startDevice`, a `useEffectEvent`, does `mount.device ??= Device.make(…, { …, queryClient: mount.client })`, `setDevice`, `void hello()`. The mount keeps its first device, so StrictMode's effect/cleanup/effect makes one device and one bring-up (`hello` answers its first call to every later one). The effect's cleanup ends nothing. Who gets a device is as before: the first userid, for the life of the mount; another userid later shows `'starting'`. `GiverConfig` now omits `queryClient` from `DeviceOpts`, and ours goes last.
  * **Before the effect** the device state is null, so `shownOf` shows `'starting'` for a string userid and `'signed_out'` for none, on the server and on the browser's first render alike.
  * **Registration**: a second effect sets the giver's `mounted` to the mount, and its cleanup clears it if it is still this mount. The calls that are not hooks (`signedIn`, `demandDevice`, `demandBank`, `demandVault`, so `withWhisper`, `putBoxOnce`, gatings, `useStrengthVerdict`'s `judge`, `lock`…) read `mounted?.device`, and refuse `absent_vault` (`NobodySignedIn`) with none. Two Providers mounted at once: the calls act on the one mounted last, until it unmounts (one doc line, tested).
  * **Our hooks observe our client**: `Shown` (the context value) now carries `client`. `useBox`, `useGate`, `useBoxList` and the `useQueryOptions` factories pass it to `useQuery(options, client)`. Outside every Provider the context default holds `outsideClient`, a plain `new QueryClient()` made once per giver, where every query skips its fetch.
  * **No `queryFn` on a record hook once up**: the minder's default (`#setQueryDefaults` at `hello`) fetches, and its cache's `onSuccess` settles the record. While not up, `queryFn: skipToken`.
  * **`useGate`** observes the whole gate (`GateStored`) and selects through `gateShownOf`, then the host's `select` (default `liveGateOf`). The wrapped bankKeys sit in our client, never in a hook's `data`.
  * **`useBoxList`** observes the minder's listing query of #827 (its default queryFn lists). No effect, no `tryList`. `select: hostLabelpathsOf` keeps the host's labelpaths. A refused list is the hook's `error`.
  * **`refetchMarked(minder)`**: the spike's `refetchBehinds`, extended to the listing. On a soon's `success` or an item's or listing's `invalidate`, `refetchQueries({ queryKey, exact, type: 'active' }, { cancelRefetch: false })`. Subscribed in the Provider by an effect on `device`, unsubscribed by its cleanup. The minder's `refetchType: 'none'` is unchanged.
  * **Options narrowed**: `BoxQueryOpts` is `Pick<UseQueryOptions, 'select' | 'placeholderData' | 'notifyOnChangeProps'>`; new `GateQueryOpts` is `select` and `notifyOnChangeProps`. At runtime each hook passes only those (`es-toolkit`'s `pick`, already a dependency).
  * **New host API, needed by the factories**: `Knock.queryClient()` (the mounted provider's client, or `outsideClient`) and `BoxQueries.client` (from `useQueryOptions`). A host's `useQuery(Knock.boxQuery(…))` in its own client would now find no `queryFn`.
  * **Gone**: `react-bridge.ts` and its tests, `GiverMount`, `GiverEvent`, `ListingQueryDefaults`, `getBoxListing`, `getBoxShown`, `getGateShown`, the Provider's `useQueryClient()`.
  * **Tests**: `tests/giver/record-hooks.test.tsx` (17), rewritten from the bridge's tests and the spike's `one-cache.test.tsx`: the acceptance tests (a hook mounted signed out, and one mounted at `'starting'`, show the record after sign-in with no remount and then a revision the watch tells of), the minder's defaults on the hook's query, the four orderings (no timer, no microtask juggling), listing and gate. In `react-giver.test.tsx`: server render (`renderToString`) shows `starting`/`signed_out` and makes no device; hydration with no mismatch; StrictMode makes one device; two mounts of one giver have two devices with separate clients and separate lock state; unmount leaves the non-hook calls refusing and ends nothing; two Providers at once; no `QueryClientProvider` needed for record hooks; options narrowed. `world.clients()` and `world._cheat_devices()` in `provider-world.ts`; `expectTextUnheld` takes one client or several.
* **Decisions made**:
  * **A plain object as the mount**, a ref in effect, over a class with a private `#device`: one field set once by one effect.
  * **`setDevice` in the effect** over a `useSyncExternalStore` on the mount: no subscribe machinery for a value set once.
  * **Registration, as the brief proposed.** Nothing plainer found: the hooks reach the mount through context, and only the non-hook calls need the registry.
  * **`refetchMarked` covers the listing too**, so a mounted `useBoxList` lists again when the minder marks its listing stale, as it did under the bridge.
  * **No `staleTime` override on the listing**: the old `ListingQueryDefaults` set `Infinity`, which would make the bare listing (dataUpdatedAt 0) read fresh and never list. The listing takes the minder's own staleTime (an hour by default).
  * **The provider no longer calls `useQueryClient()`**, so it no longer refuses outside a `QueryClientProvider`. Keeping a call only to throw would be a predictive throw.
* **Deviations**: none from the brief's list. The test `tests/wontfix/stage-change-suspends.test.tsx` changed its call (it must hand `useSuspenseQuery` the giver's client, and its type-only cast moved to the options); the behaviour it demonstrates still stands, so it was not inverted. `makeKeyEditor` in `react-giver.test.tsx` now records the action's result in a layout effect: a passive effect raced `findByText` once in four runs.
* **Discoveries**:
  * **The stale-time function's `0` arm is inert**: with it replaced by `Infinity`, every test passes (an item behind is invalidated, so stale anyway). The `Infinity` arm does act: it replaces the minder's own staleTime (an hour) on an item a hook observes, so an observed item never ages into a refetch on mount or focus. Left as it was.
  * **A bare listing shows**: from the device's start until the first list lands, `useBoxList` shows the boxes heard of (usually `[]`), with `isFetching` true once the bank is up. Envman's `EnvList` would flash "No secrets yet." for the length of that first list. The old hook answered `undefined` until its own list.
  * **A remount makes a new device**: the device lived for the page in the giver; now it lives for the mount. A host that remounts its root starts a second device and a second bring-up, and the first keeps its watch open (nothing ends it: endings are out of scope).
  * **A host's options on our query**: the observer's options become the minder's query's while observed; narrowing closes this for the host, but the giver's own `staleTime` and `structuralSharing` still replace the minder's there, as in the spike.
* **For the Coach**: the bare-listing flash, the remount making a second device, and the two new host members (`Knock.queryClient()`, `BoxQueries.client`), whose names wait on the surface thread.
