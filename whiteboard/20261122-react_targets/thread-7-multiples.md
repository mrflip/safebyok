# Thread 7: multiples (2026-11-22)

Branch `20261122-multiples`, PR #823, stacked on #821 (on #820, #818, #817). Proved: see the last line of this file.

So a host may write its forms as TanStack mutations as fully as as React 19 Actions: three small additions, and a fourth the Coach ruled in after to `packages/safebyok-react-lean`, each its own commit with its tests, and one empty changeset (`.changeset/20261122-multiples.md`).

* **Built**:
  * **`putBoxMutationOptions(boxNamed, opts)`** (`src/giver/react-giver.tsx`, on the bank giver beside `putBoxAction`), and the type `PutBoxMutationOptions` (`UseMutationOptions<LiveOf<BoxRecord>, Error, FormData>`). The module-level helper `formReaderOf(opts)` (Helpers section) is what both it and `putBoxAction` now call: it checks `opts`, wraps the host's two functions with `bulletproofHandlerOf` and `HostCallbackOpts`, and returns a reader that checks the form is a `FormData`, reads the patch and secrets, and empties the form in a `finally`. `putBoxAction` lost its inline copy (`takeForm`) and calls `readForm(form)`; its `catch` and its results are as before. The options carry `networkMode: 'always'` and `retry: false`, each with a `//` comment (the retry comment matches `FormMutationDefaults`'). `mutationFn` is async, so it rejects with the refusal, or with what `whisperOf` or `sidecarOf` threw.
  * **`SubmitButton`'s `isPending`** (`src/parts/submit-button.tsx`): same name, type and doc line as `PassphraseInput`'s, OR'd with `useFormStatus().pending`; it is destructured, so it reaches no DOM attribute. `UnlockForm` and `PasskeyUnlockButton` use `SubmitButton` with `isPending={isUnlocking}` and their `whilePending` phrases again.
  * **`refusalTextOf`** exported from `src/kit/index.ts` (not from the package root, which does not export the kit), with a doc block and an `@example`.
  * **Tests**: `tests/giver/react-giver.test.tsx`, `describe("putBoxMutationOptions")`, eight cases: writes the box through a host's own `useMutation` and `<form action={(form) => put.mutate(form)}>`; after a write that lands and one that is refused, the mutation's retained `variables` `FormData` has no field and `expectTextUnheld` and `holdsText` find no secret in React's tree, the QueryClient or the mutation result; `whisperOf`'s `Error` is the mutation's `error`, the same object; a non-Error throw is wrapped with the value as `cause`; the options carry `networkMode: 'always'` and `retry: false` and a write started offline lands; the key under a user and under none; bad opts refuse synchronously; a non-`FormData` rejects `bad_record`. `tests/parts/submit-button.test.tsx`: two cases for `isPending`. `tests/kit/phrases-kit.test.ts`: `refusalTextOf` imported from the kit's entry answers the trouble text for seven non-refusals. The existing kit tests passed unedited.
  * **Addition 4, `secretFieldnames`** (its own commit, after the three). `PutBoxActionOpts` gains `secretFieldnames?: readonly string[] | undefined`, checked as an array of non-empty strings. `formReaderOf` deletes, in the same `finally` as before, only those fields, each with `popField`; left out, `emptyForm` as before. `PutBoxActionResult` is still one union of two shapes, and both now carry `texts: Readonly<Record<string, string>>`: `{ box, err: null, texts: {} }` for a write that landed, `{ box: null, err, texts }` for a refusal, `texts` being the first string of each field left in the form (`textsOfForm`, a Helpers function; a file's field is left out; `{}` for a non-FormData and when no names were told, since every field was then deleted). `putBoxAction`'s `catch` only gains `texts: textsOfForm(form)`. The twin honours the option and has no new member. Doc blocks name the duty to list every secret field, and `putBoxAction`'s `@example` restores `title` with `defaultValue`. Tests: refused action with names (texts, FormData, the Title input restored by React's reset, no secret in the result, the forms, the React tree or either cache), landed write (empty texts, empty Title), no names (all deleted, empty texts), bad option refuses, twin deletes only the named fields. Nothing about it wanted to grow.
* **Decisions made**:
  * **A `mutationKey`**: the gate verbs' options have one, so the options carry `formMutationKeyOf({ userid, banklabel, verb: 'putBox' })`, i.e. `['sok', userid, banklabel, 'putBox']`, `userid` from `signedIn()` as `unlockMutationOptions` does. It is per bank, not per box: the helper takes a verb, not a labelpath. A host that wants one per box overrides it in its own `useMutation`.
  * **The `FormData` check moved into the reader** (`formReaderOf`), outside its `try`, so a non-`FormData` refuses `bad_record` without `emptyForm` running on it. `putBoxAction` still resolves that refusal.
  * **`formReaderOf` is a module-level function in Helpers**, not a closure in the bank giver: it needs nothing of the bank (lint's `consistent-function-scoping` asked for it).
* **Deviations**: none from the handoff.
* **Discoveries**: `refusalTextOf`'s `default` arm returns `err.message` for a `condition` refusal with no phrase of its own, so a host gets that condition's raw message, not "Something went wrong". The doc block says so. Whether every `condition` message is fit for a user is not checked here. The kit is not exported from `src/index.ts` (it has its own entry), so `refusalTextOf` is reached as `safebyok-react-lean/kit`.
* **For the Coach**: the per-bank (not per-box) `mutationKey`; and the `default` arm above.
