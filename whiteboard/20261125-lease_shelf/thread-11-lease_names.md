# Thread 11: lease names (2026-11-25)

Branch `20261125-lease_names`, PR #927, stacked on #924 (thread 10). Proved: `pnpm --filter safebyok test` (lint-clean, typecheck green, 36 files, 2,292 tests); `pnpm --filter safebyok-react-lean` typecheck and test (23 files, 339 tests).

* **Built**:
  * **One devicetok per user** (the Coach: "per user+browser, there is already a banktok"). `deviceDB.ensureDevicetok(userid)` and `device.ensureDevicetok(userid)` take the userid alone; the memory store keys it `ckeyOf(userid, 'devicetok')`, the IndexedDB store `[userid, 'devicetok']` (`DevicetokScopepath`). `Proving` asks for the devicetok of the user of the bank it is stamped for. A host-given devicetok still wins. The ctx is unchanged: it carries the devicetok's bytes as before, only where it is kept moved.
  * **A lease names itself** (the Coach: "everything lease-y should be at lease/label (where label happens to match the gate), referencing it own label"). `LeaseLabelpath` is now a value too, its helper `LeaseLabelpath.of(gateLabelpath)` (`src/shapes/shapes-stamps.ts`) the one place the label is chosen: `lease/` and the gate's label, refusing `bad_record` for a labelpath that is not a gate's. It replaces `leaseLabelpathOf` and `leaseScopeOf`, exported from `safebyok` and `safebyok/storage` in their place. `Lease.shellOf` uses it; the world peeks by the lease's own scope (`#peekStored(leaseScope)`), taken from the shell in `#leaseFollowed` and from `LeaseLabelpath.of(Labelpath.MainGate)` in `#followStored`.
  * **The test the Coach asked for**: "leaves the gate stored as it is where a lease it takes up cites a newer revision of the gate" (`tests/models/world.test.ts`). It holds: the stored gate deep-equals its snapshot, and the tab takes the lease up, unlocked and not softlocked. `#softlockPastGate` returns where the gate's revseq is not past the lease's, and nothing in the take-up writes the gate.
* **Decisions made**:
  * `LeaseLabelpath.of` is a companion object, as `Labelpath.labelOf` is, which takes TODO.md's entry. It validates its argument at entry (`PerKindChecks.gateLabelpath`), since it is exported.
  * `#leaseFollowed` makes the shell first and peeks by its scope (the shell's `userid`, `banklabel` and `labelpath`, destructured), so the lease's labelpath is derived once there. Set aside: keeping `#peekStored(gateScope)` and deriving inside it, which is `leaseScopeOf` inlined and leaves the world naming the lease by its gate.
  * No `LeaseDBVersion` bump: a devicetok row filed per bank by an earlier build is orphaned in IndexedDB and never read (pre-1.0, no migration). The changeset says a host sees a fresh devicetok minted once per user.
* **Review rework** (the high review): **the live lease's label-to-gate check stands.** It was dropped in the build, on the Coach's "label happens to match the gate" read as a choice made once rather than an invariant; the review found that without it a record at `lease/gate` naming another gate was no longer refused at peek as `damaged_lease` bad news, but taken up as un-unlockable, so every unlocked tab dropped its lease and announced `lock_taken_up` silently. Restored: `isOfItsGate`, now reading `LeaseLabelpath.of` (the label is still chosen once, there), the phrase `LeaseLabelpathOfOtherGate`, and its two test cases, `lease.test.ts` and the deviceDB battery. Two additions it needed: a lease's `gate_labelpath` is checked as a gate's (`PerKindChecks.gateLabelpath`, was any labelpath), and the refine runs only once every field passes (zod 4's `when`), since `LeaseLabelpath.of` throws on a labelpath that is no gate's and a throw inside a refine escapes `safeParse` in `peekLease`; a test case each for a `gate_labelpath` of `box/openai`. Set aside: guarding inside `isOfItsGate` with `Labelpath.isOfModelkind`, a second check of the same fact. Also from the review: VOCABULARY's devicetok and lease record rows, `LeaseLabelpath.of`'s doc block (no refusal catalogue), `ensureDevicetok`'s alignment, and alphabetical import order.
