## Eyebrows, ranked

**E1. Every Convex failure that isn't a refusal comes back `storage_unavailable` ("try again shortly"), but the Convex client only rejects when the function itself failed, and those mostly repeat.** `convex-vault-db.ts:189`, `refusalOf`: `if (! (thrown instanceof ConvexError)) { return DB.storageFailed(oplabel, thrown) }`. Convex 1.49's `request_manager.js` `restart()` resends in-flight mutations on reconnect, so a lost connection never rejects `client.mutation`; what reaches the catch is a server-side function error: a validator failure, an oversize document, a `$` key, a bug, or `.unique()` meeting two documents (`things.ts:136`, which says that "should fail loudly"). PostgresVaultDB tells transient (`storage_unavailable`) from lasting (`unexpected_error`), `postgres-driver.ts:31`. *Origin:* carried from convex-big unchanged. *Cost:* one branch, but it sets the retry meaning of every Convex failure. *Flavour:* guidance gap; the pending sidecar-key row is one case of it. *Settle:* confirm from Convex's docs that `query`/`mutation` reject only on a function error, then rule the kind for that class.

**E2. The core's contract says `storage_issue` when a write's storage disagrees with the classifier; both new-core adapters refuse `unexpected_error`.** `adapter-vault-db.ts:220`: "`storage_issue` where no verdict explains the refusal". Postgres `postgres-driver.ts:80` `storedNothing(): VaultError { return DB.unexpectedError(...) }`; Convex `convex-vault-db.ts:203` `storedOutOfStep()` the same. Big's `StorageIssue` phrase ("the database or its storage adapter needs someone to look at it") fits: an installed component or SQL out of step with the client. Your Q6 ruling (only a failed check of a received record) doesn't clearly cover `written: null` where the classifier found a write. *Origin:* Convex follows the Postgres model; predates the sprint. *Cost:* one thrower per adapter. *Flavour:* guidance gap, or guidance wrong. *Settle:* rule the kind; fix the core doc or the two throwers.

**E3. The Postgres model B was told to follow carries lifecycle-crossing guards `#no-slop-crossings` forbids; Convex copies two.** `convex-vault-db.ts:132–147`: `let isWatching = true`; the result handler starts `if (! isWatching) { return }`, the error handler `if (isWatching) { onBadNews(...) }`: a result or error after unwatch, a millisecond overlap that earns no guard. A third guard (unsubscribe once) has a real reason: "Convex counts a query's watchers… A second call would end another watch". `postgres-vault-db.ts:188–206` has four `isListening` guards; indexeddb's `doWatch` none. *Origin:* carried from convex-big, and drawn by the Postgres model. *Cost:* a flag and two branches per callback path. *Flavour:* guidance gap: a model handed to workers contradicts a CLAUDE.md rule. *Settle:* can an `onUpdate` fire after unsubscribe? If not, the two are dead; then decide whether the models get cleaned.

**E4. "Modelled on PostgresVaultDB" doesn't describe the code: the write path is indexeddb's and convex-big's shape, and classifies twice.** The component (`things.ts:57–70`) checks the ask with `checkedWriteAsk`, runs `classifyWriteThing` inside `wouldWrite(...)`, writes on a write act, and returns the Things as fetched plus `written`; the client (`convex-vault-db.ts:89–100`) classifies the same Things again, cross-checks `written` (`demandUnwritten`/`checkedWritten`), and throws `StoredOutOfStep` on disagreement. The double run is the price of a client that trusts nothing storage says. Costs: the core, and safebyok-big through its re-exports, is bundled into the host's Convex deployment; component and client must upgrade in lockstep; `read_tc: DB.readTcNow()` (`things.ts:63`, `:80`) mints a throwaway id for the classifier's type. *Origin:* running the step in the datastore is drawn by AdapterVaultDB's doc ("A datastore that can run code of its own may run the whole step there"); the cross-check carried from big's `storedAsWritten`; the plan named the wrong model. *Cost:* 2 branches per write verb, a helper pair and a phrase. *Flavour:* draft off given the code; code looks right. *Settle:* confirm client re-classification is the intended price.

**E5. Two tests assert less than their titles.** (a) `tests/scripts/release.test.ts:16`, "releases neither safebyok-big nor a package on it", asserts only that no public name ends `-big`. All five public packages (convex, fastkey, indexeddb, postgres, react) reach big through private `safebyok@0.0.0`; nothing in `releaseProblems` refuses a public package with a private peer, so "publishing waits for the core" holds only until someone runs a release. *Origin:* new in A. *Flavour:* title off; the missing check a guidance gap. (b) `convex-vault-db.test.ts:166`, "stores one document for each Thing, writing only the Thing a write cites", counts documents and reads the gate back equal; a rewrite with identical content passes. *Flavour:* solution slightly off. *Settle:* a spy on `db.replace`/`db.insert`, or narrow the title.

**E6. The watch ships the whole bank to every watcher on every change.** `things.ts:93` `watchThings` returns every Thing of the bank; each update `JSON.stringify`s every Thing twice and diffs (`convex-vault-db.ts:217–228`). A box put, the frequent op, re-sends every box's ciphertext to every watcher. The README says a bank past 16 MiB "makes its watch go quiet" (`README.md:92`); in code a failing query reaches `onBadNews`. *Origin:* carried in kind from big's `watchRows`; Postgres notifies one Thing at a time. *Cost:* O(bank) per write per watcher. *Flavour:* redesign? (a query over Things changed since a cursor); low priority while banks stay small. *Settle:* how large banks get.

**E7. Public surface carried over without a caller.** `src/server.ts:14–15` exports `safebyokErrorkindVals`, `SafebyokErrorkind`, `isSafebyokRefusal`, used only by this package's tests; big's `AssertEqual` tie was dropped, so the kind list lives three times untied (`refusals.ts:8`, the union, the `discrim` checker). `./testing` publishes `FakeDeployment`, a 325-line fake Convex sync server with `_cheat_` methods; `./test` ships raw TypeScript using `import.meta.glob`, which only Vite understands. *Origin:* carried verbatim. *Cost:* contract surface at the next public minor. *Flavour:* guidance gap: "what is exported is a contract" pulls against "port what still fits". *Settle:* decide what stays public in `/server`, `/test`, `/testing`.

**E8. `postgres-driver.ts` is what the split left, not one concept.** Driver types and pg error mapping fit the name; `jsonOrNull` (notice parsing), `storedNothing` (a vaultDB refusal) and `listenOrNull`/`unlistenOnceListening` (watch plumbing) don't; only `postgres-vault-db.ts` uses it. `refusalOf`, `isTransient`, `causeOf`, `codeOf`, `PgConnectionLost`, `listenOrNull`, `unlistenOnceListening` are line-for-line copies of `safebyok-postgres-big`'s (the sanctioned port while big is frozen). *Flavour:* can't tell. *Settle:* fold into `postgres-vault-db.ts`, or narrow the name.

**Checked, and clean.** The identity gate holds: `server.ts:66` `checkCaller` reads `userid` before the component re-parses the ask; `checkWriteInvariants` refuses a record of another scope; `birthPutsOf` takes every put's scope from the ask. Postgres and fastkey changes outside the split are import moves only. The new `storage.ts` exports (`birthPutsOf`, `checkedBirthBankAsk`, `checkedWriteAsk`) are used, not reimplemented.

## Undergrowth

**Control primitives: little, almost all carried.** The `isWatching` flag (E3). A `seen` baseline map in `doWatch` (drawn: Convex re-sends the whole result). `FakeDeployment` in `src/testing.ts`: a promise-chain job queue (`:107` `private work: Promise<void>`), a `ts` counter, sockets that deliver on `setTimeout`, a one-turn wait in `_cheat_arrange` (`:145`), all carried, test-only but published (E7). Postgres's held `listening` promise and `isListening` flag moved in the split. No retry, abort controller, lock, generation or token in the changed source.

**New mechanisms: none beyond the plan.** `things.ts` replaces `banks.ts`, `convex-vault-db.ts` replaces `convex-bank-db.ts`; `postgres-driver.ts` is the split (E8); the test's `madeOn` WeakMap is drawn by indexeddb's `dbNameOf`.

**Non-standard JavaScript: mild, carried.** Thunk wrappers each holding one try/catch: `askFor(() => DB.AskChecks.getAsk.parse(sent))` (6 calls; turns a refusal into a `ConvexError`, since Convex withholds other errors' text), `wouldWrite(() => DB.Classifier.classifyWriteThing(...))` (2; a refusal becomes "no write", which the client reaches itself), `runOrRefuse('getThing', () => this.#client.query(...))` (5; "ConvexReactClient.query can throw synchronously"). `aboveIn` (`things.ts:161`) destructures out of a `Promise.all`, slightly golfed. `childrenIn`'s range trick ("'0' being the character after '/'") is drawn by indexeddb. `isSafebyokVaultApi` (`convex-vault-db.ts:257`) accepts any module with the six names (`api.other.getThing` passes) and refuses only the whole `api`: an interface check. Safety hatches: two `eslint-disable-line unicorn/prefer-private-class-fields` on the `_cheat_` methods.
