# Thread 4: minder_writes (2026-11-19)

Branch `20261119-minder_writes`, PR #TBD, stacked on #757. Proved: `safebyok` lint and typecheck clean; `tests/minding` 245 tests green (thing-minder 179). `pnpm justify` not yet run.

* **Built**
  * `ThingMinder.tryWrite(ask: WriteAsk): Promise<WriteThingAnswer>` (`packages/safebyok/src/minding/thing-minder.ts`, section `Writing`). It sends the ask, sealed and made by the bank (`Bank.makePutAsk`, `makeDelAsk`), to the vaultDB's `tryWriteThing`, lands every record the answer carries, then resolves the answer as it came: good or refused, never thrown.
  * What lands (`recordsOfWriteAnswer`, a module helper): `val` (the record written, or under `passed` the live Thing found) or a refusal's `dbhas`; the world's bank (`omit(world, ['maingate'])`) and `world.maingate`; and each Thing in `tracked` that is not `'same'`. They land in one `TSQ.notifyManager.batch` through `#sendToTSQ`, as `list` does, so each goes through the car merge and `#joinParentListing`. A birth joins its parent's listing (where one is cached). A del's tombstone makes the car `gone` and stays listed.
  * Before asking, `tryWrite` follows `tryAt`'s lead: not minding, or a scope outside the bank (or an ask that is no bag), answers `{ ok: false, act: 'unclassified_storing', world: null, dbhas: null, err }` (`disabled` or `bad_record`) without calling the vaultDB.
  * Three invariants added to the class's `## Invariants`; the class doc's sources list now names the write's answer as the fourth.
  * `Phrases.MinderNotStarted` and `Throwers.minderNotStarted`'s doc name writing beside reading.
  * Tests (`tests/minding/thing-minder.test.ts`):
    * `ThingMinder.tryWrite`: 15 cases. Answer as the vaultDB gave it (same object); world's bank and gate land; a tracked root box lands; a `stale_write` leaves the car's newest at `dbhas`; nothing is cached (no car, no listing change, no event) while the write waits; a listener is told the new car before a caller's `await` returns; a notice of the same write after the answer, and an answer after the notice, each leave the car and listing the same objects; a delete leaves the car `gone` and the tombstone listed; a real born bank's `sealBox` + `makePutAsk`, then `tombstoneBox` + `makeDelAsk`, through `tryWrite`; refusals before asking (not minding, other bank, not a bag); an answer arriving after `goodbye` lands nothing.
    * Two test vaultDBs: `QuietVaultDB` (its watch tells nothing, so a write's notice reaches the minder only when the test hands it) and `LateWriteVaultDB` (holds writes after storing, once `hold()` is called).
    * `Listings in any order` gains the write step (births `box/cohere`): every order of four steps, 24, generated by putting the write at each place of the six earlier orders; both runs. `listingAfter` now runs over a `QuietVaultDB`, so the write step is the answer alone (checked: dropping the landing fails 44 tests).

* **Decisions made**
  * **`tracked` records land too.** The handoff listed the stored record, `dbhas`, and the world's bank and main gate; `tracked` is the one other place an answer carries records, and "every record an answer carries lands" covers it. The watch also delivers them, so this only makes them land sooner. Small to drop if unwanted.
  * **The catch covers only the checks before asking.** The vaultDB's try-verbs never throw by contract, so `tryWrite` does not wrap the call: a vaultDB that rejects is a broken adapter, and its rejection propagates, as `list`'s does.
  * **The minder checks only readiness and scope.** The vaultDB checks the whole ask (`checkedWriteAsk`) and refuses a bad one in its answer, which `tryWrite` passes on.
  * **The "before resolve" test sets its flag after the `await`**, as a host would see it: the lint rule `unicorn/prefer-await` refuses `.then`.

* **Deviations**
  * None from the plan. The delete line followed the Coach's correction: a box's delete goes through `tryWrite` and is tested; nothing of root deletion or cascade.

* **Approaches set aside**
  * Landing the answer outside a batch, record by record: a listener of a listing would hear it between cars; the batch matches `list`.
  * A two-row table for the answer/notice orders: `vitest/no-conditional-expect` refused the branch; two plain tests instead.

* **Discoveries**
  * `MemoryVaultDB`'s watch notifies a write on a microtask queued inside `tryWriteThing`, so in a test with the real watch, the notice can land before the write's answer does. A test that means to show the answer's landing needs `QuietVaultDB`.
  * The test file is at 1,484 lines, at STYLE.md's split threshold (about 1,500). Thread 5's tests will push it over: split it into `tests/minding/thing-minder/` then.
  * **For Part 2 (`putBoxOnce`):** after a `stale_write`, `at(scope).newest` is the record the vaultDB reported (whole, so the car is `full`), ready to seal against. `tryWrite`'s answer is the vaultDB's own object.
