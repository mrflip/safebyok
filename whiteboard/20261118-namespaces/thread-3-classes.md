* **Built**:
  - `models/base-thing.ts`: `BaseThing`, abstract and not generic, declares the Thing fields (with their doc blocks) and carries the record guards as statics: `isLive` (new), `isTombstone`, `isGone`, `isVoidSentinel`, `isWhole` (was `isWholeRecord`), `isSparse`, and `cmp` (was `cmpThings`), `haveSameScope`, `sparseOf`. `static readonly modelkind: Thingkind | null = null`. Each guard is `this: Kinded<KindT>` and reads `this.modelkind`; the narrowed types are named for hovers: `LiveOfKind`, `TombstoneOfKind`, `VoidSentinelOfKind`, `WholeOfKind`, over `RecordOfKind<KindT>`. The kind is checked with `Labelpath.modelkindOf` after the scope-and-citation check (`ThingChecks.scopedCited` with `am`).
  - `models/thing.ts`: `Thing<RecordT, ScopeT, StampT> extends BaseThing`, the old BaseThing: protected constructor, `#record`, `pickle`, abstract `scope`/`stamp`. `Bank` and `Gate` extend it and set `static override readonly modelkind`.
  - `models/base-box.ts` (git mv of core-box.ts): `abstract class BaseBox extends Thing<BoxRecord, ThingScope, BoxStamp>`, modelkind `'box'`, the old CoreBox's statics unchanged; `Object.freeze(BaseBox satisfies Sealer<...>)` still holds. Its `no-extraneous-class` disable is gone.

  - `ShellOf<RecordT>` pins `revtok`, `revseq`, `lifeseq` to the void ones; `VoidSentinel = ShellOf<ThingRecord>` (own commit).
  - `Bank.tryGetBox`: `BaseBox.isLive(val) || BaseBox.isTombstone(val)` narrows the answer to a box, and both casts went (the `Shell.of(...)` one was already redundant since #744's single fmt).
  - `AnyThingRecord = AllUnionFields<ThingRecord>` (type-fest 5.10.0, a runtime dependency, its own `deps:` commit), exported beside `ThingRecord`.
  - Entry points: index.ts and storage.ts export `BaseThing` and `Thing` (values, since the guards are called on them) and the kind types; core.ts adds `BaseBox` in place of `CoreBox`. `tests/index.test.ts` forbids `BaseBox` on the front door in place of `CoreBox`.

* **Decisions made**:
  - **The narrowing filters a union by kind** (`MembersOfKind<ValT, RecordT>`: a member of `ValT` wider or narrower than the kind's record stays, any other is `never`). The plain `ValT & Sparse<RecordOfKind<KindT>>` of the handoff does not narrow a mixed `ThingRecord`: kinds differ only in their bodies, so `BankRecord & Sparse<GateRecord>` is not `never`, and TypeScript keeps it. Each branch of the conditional is `ValT` or `never`, so TypeScript accepts it as a predicate type with no `ValT &`. Checked: `Gate.isTombstone(rec: ThingRecord)` narrows to a gate tombstone, `BaseBox.isTombstone(unknown)` to a sparse box tombstone, `Gate.isTombstone(box: BoxRecord)` to `never`, and the false branch of `Thing.isVoidSentinel(DeliverableThing)` leaves `ThingRecord | Sparse<ThingRecord>`.
  - **`isSparse` returns `boolean`, not a predicate**, as today: a predicate's false branch would take a whole live record to be no record at all (`never`). `isWhole` keeps today's predicate (the void sentinel is whole but typed as a record, as `isWholeRecord` was).
  - **`isWhole` and `isSparse` take a `Sparse<ThingRecord>`**, as today, since they read the labelpath before checking; the other guards take anything.
  - **`ShellOf` pins revtok, revseq and lifeseq only**, as the handoff lists. `born_at`/`written_at` are left as `EpochMillis`: `TH.boxShellOf()` builds a sealable shell at `T0`, which the sealer accepts, and pinning the times would have retyped that fixture.
  - **Kind-generic callers go through `Thing`**, including storage (`adapter-vault-db.ts`, `thing-classifier.ts`); `models/thing.ts` imports only big's Helpers and base-thing, so no cycle.
  - **The tests that gave the bank or a minder a box record as its root box** (safebyok's bank.test and thing-minder.test, safebyok-react's minder-giver world) now give a live one (`{ ...TH.rootBoxOf(), am: 'a' }`), since a `BoxRecord` of either liveness no longer passes for `ShellOf<BoxRecord>`. Changing `TH.rootBoxOf()` to return `LiveOf<BoxRecord>` was tried and set aside: `replaceAskOf`'s `WriteAsk<LiveOf<BoxRecord>>` stops being an object type.
* **Deviations**:
  - `BaseThing` is not generic (the handoff allowed "as needed"): its only use of `RecordT` was `fmt`, now one value for every kind, and the linter refuses a type parameter used once.
  - The static field `modelkind` on `BaseThing` carries `// eslint-disable-line @typescript-eslint/class-literal-property-style`: the house config wants literal readonly fields as getters, and a subclass's `static override readonly` field could not override a getter. The subclasses' fields are `override`, which the rule skips.
* **Discoveries**:
  - TypeScript refuses a detached guard call (`this` is `void`), so the runtime throw is reachable only through a cast; no test pins it.
  - Where narrowing a mixed record to one kind comes up: not in thing-car.ts (every guard there is kind-generic, and its per-kind step is `ThingChecks.ofLabelpath(newest.labelpath).record.parse(fullest)`, a runtime dispatch); not in thing-minder.ts as a record guard either: `at`, `tryAt` and `get` cast the car to `CarAt<LabelpathT>`/`TSQGotAnswer<ThingAt<LabelpathT>>` by the labelpath's type, and the `carQuery.state.data` cast is TanStack's `unknown`. The one place in src that narrows a mixed record to a kind is `Bank.tryGetBox`, done here. `Bank.put`'s `answer.val as BankRecord` could be `Bank.isLive(val)`-checked the same way; left, outside the handoff.
  - No place in src reads optional kind-specific fields from a record of any kind, so `AnyThingRecord` is only exported.
