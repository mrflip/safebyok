* **Decisions made**:
  - **Big's refusals are re-exported from one specifier, `'safebyok-big'`, in core and storage both.** tsdown's bundler cannot see through an external package, so the same `VaultError` re-exported from `'safebyok-big'` in core and `'safebyok-big/storage'` in storage read to it as two bindings: `NAMESPACE_CONFLICT`, and the name dropped from the front door's dist. Each big name the two entries share now comes from the same specifier in both.
  - **`import-x/export` is disabled around the two `export *` lines of index.ts** (a block `/* eslint-disable */ ... /* eslint-enable */`). The rule reports every name core and storage share, though each is the same binding; TypeScript refuses a name the two export as different bindings (TS2308), and the test checks each value. A front door that `export *`s from core alone and lists storage's extra names by hand was set aside: the list would drift from storage.ts.
  - **`safebyok/browser` lists big's browser names rather than `export *`, and leaves out big's `StrengthChecker` for the new core's.** The two types have the same shape, but a host should find one `StrengthChecker` across the new core's entries; an `export *` with an overriding named export is legal, but `import-x/export` reports it.
  - **`Banklabel` on the front door is the new core's**, not big's: both are `string`, and the new core defines its own. The giver's `Banklabel` moved to it. `UserID` is big's (the new core calls its own `Userid`), re-exported as item 4 asks.
  - **`DefaultStrengthChecker` and `guardStrengthChecker` stay on the front door only**, as the handoff lists; the types they use are on core.
  - **Checkers moved onto storage, not only the front door**: big's storage entry carries them for the same reason, and postgres's vault-db reaches them there.
  - Left off every entry (each a second ring of big's own types, or a const reached only through `typeof`): `RefusalRows` (big exports it on no public entry), big's `BadAct` (named by `RefusalMeta`; the new core has its own `BadAct`), the validator's `Kit`/`KitWith`, `VoidLifeseq`/`VoidRevisionSeq`/`VoidRevisionTok` (`ShellOf` pins `typeof` each), `Watcher` (a private type in `MemoryVaultDB`'s protected `doWatch`), `guardKeyDeriver` (in proving.ts). The review (35a4a349d) exported `Capacity`, `ObjCheckOpts`, `Refusing`, `Story`, `ConsistencyRefusal`, `MaskOpts` and `type Novel`.
