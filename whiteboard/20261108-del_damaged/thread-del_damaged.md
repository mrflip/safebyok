# Thread del_damaged: a damaged box row has its own delete (2026-11-08)

Branch `20261108-del_damaged`, PR #608, stacked on #607. Justify: green; every adapter suite ran here (IndexedDB through fake-indexeddb, Postgres through pglite, Convex through convex-test, GraphQL over the memory adapter).

* **Built**: `vaultDB.delDamagedBox(tombstone, boxprops)` and `tryDelDamagedBox` on the `VaultDB` interface and `AdapterVaultDB`, with a `doDelDamagedBox` hook in memory, IndexedDB, Postgres and Convex, and a transport through GraphQL (`safebyokDelDamagedBox`, `SafebyokJson`) and Convex (`delDamagedBox`, `v.any()`). The check is one shared helper, `SX.isDamagedBoxMatch(raw, boxprops)`: `boxprops` fails `SX.boxRowDuckish` (the box row, `strip` at its top level), is not a newer `fmt`, and `stableJsonify` of it is that of the stored row. `doDelBox` lost its damaged branch. `damaged_rows` entries carry `boxprops`, the raw row. `BoxListing.delDamaged` / `tryDelDamaged` own the operation; `vault.tryDelDamagedBox` is a one-line delegate. The `del` override on `BoxListing`, which only existed to clear damaged rows, is gone.
* **Decisions taken**:
  * Each adapter's two delete hooks share one private step (`#delBoxWhere`, Convex's `storeBoxTombstoneWhere`) taking the predicate, so the transaction is written once.
  * Refusals: no new kind. A mismatch, an extras-only row and a newer `fmt` all answer `damaged_row` by the existing `foundBoxRow.parse(ante)`, which names `fmt` among its fieldnames for a newer one; a healthy row answers `stale_write`, as `delBox` does; void and gone answer as `delBox` does. `req_params` come from the tombstone alone, so `boxprops` reaches no refusal.
  * `Listing.tombstoneOver` split out of `delOver`, so the listing mints the tombstone as it always has.
* **Deviations**:
  * The handoff named `delDamagedBox(boxprops)`. The verb takes `(tombstone, boxprops)`: a damaged row like `{ garbage: true }` holds no address, so the store cannot find it from the row. Set aside: a single argument bundling the two (only hides the two), and `(BoxQuery, boxprops)` with the base minting the tombstone (the base would then own a revision the client owns everywhere else). The tombstone also keeps `req_params` clear of the raw row.
* **Discoveries**:
  * The strip is top-level: nested objects in a box row (`sidecar`) stay strict, so a row with an extra field inside its sidecar counts as damaged and is deletable.
  * A row whose only fault is extra fields is listed in `damaged_rows` (the listing's check is strict) and refused by the verb, per the design: it stays listed, and `vault.tryDelDamagedBox` answers `damaged_row`. Same for a newer `fmt`. Pinned in `vault-boxes.test.ts` and the battery.
  * Convex was not awkward: the stored `box` is `v.any()`, `boxprops` crosses as `v.any()`, and the comparison runs in the mutation.
  * `notes/gallant.md` quotes the old body of `vault.tryDelDamagedBox` as its example; left alone.
  * Tests changed: `vault-boxes.test.ts` needed none (one added, the extras-only row). `vault-listing.test.ts` "leaves when the customer names its box row" reached around the guards with `boxListing.del` on a locked session; it now lists and calls `delDamaged` on the unlocked vault. The battery's "delBox deletes rubble at the sentinels" became "delBox refuses a damaged row", beside a new `delDamagedBox` battery run over every adapter.
* **For the Coach**: the G8 inspection and `notes/security.md` entry stay deferred as you recorded. The raw row now crosses as an argument. A Convex validator failure can echo the value at its failing path, and a GraphQL server can echo a variable; the tombstone is parsed before it crosses, and `boxprops` takes any value, so neither arises in the ordinary path. Worth a look in that inspection.
