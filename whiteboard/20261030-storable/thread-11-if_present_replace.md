# Thread 11: ifPresent 'replace', and two listing guards (2026-10-30)

Branch `20261030-if_present_replace`, PR #385 (base `main`), stacked on #384. Justify: green (see the PR's **Tests:** line).

**The Coach's ruling (2026-10-30), which this file now reflects:** no new operation was planned or intended. The old compare-and-swap is the only thing meant: it takes the revision and value that were there and replaces them with the new revision and value, a *versioned replace*. No attempt to patch the pre-existing server-side value is made or contemplated. The first build made `'replace'` an overwrite (storage putting over a held record when `expected` is null, then at held seq + 1); that is gone.

* **Built**:
  * `ifPresent?: 'replace'` accepted and inert: `ifPresentVals = ['replace']`, the `ifPresent` checker, the `IfPresent` type, `sendOpts = timelyOpts.extend({ ifPresent: ifPresent.optional() })` in `models-shapes.ts`. Any other value refuses `bad_option`. The docs say it is the default and only policy, the versioned replace, and that `'fetch'` is not implemented.
  * Nothing hands it to storage: `Store.put(record, expected)`, `listing.put(duck)` and `tryPut(duck)` have no third/second argument. `send` parses `sendOpts` first (so a bad value refuses before anything is staged), drops `ifPresent`, and hands the timely rest to `edit`.
  * `Store`'s doc block says in plain words, for every adapter: a put lands only if storage holds the revision `expected` names (tok and seq), or nothing when `expected` is null (a stored tombstone counts as something), else `stale_write` carrying what is stored; the record lands exactly as minted, never renumbered or patched.
  * The fake store (`tests/test-helpers/models-world.ts`): `put` refuses `stale_write` carrying the record stored for `expected` null over any held record, a **tombstone** now included (revision 0 lands only over no row); it keeps the record as given. `ifPresent` is gone from its `put`, call log and `willPut`. Nothing else compares `expected` (the full compare-and-set for a given `expected` is thread 16).
  * Guard 1, `#deliver(answer, asked, ifAbsent?)`: an answer whose `scope` differs from the scope asked refuses `bad_record` (`Phrases.AnswerOfOtherScope`), before the world is taken and before any delivery; for a refusal answer the scope guard comes first too, so the answer's own refusal is not thrown in its place.
  * Guard 2, `#demandRecordOfVault` checks every record a cached copy would make an instance of: its central and its staged (`#recordsOf` replaces `#centralOf`). A copy with another `vault_tok` in either is a cache miss told to `onBadNews`.
  * Spec (`whiteboard/20261028-storable_base/storable-spec.md`, the Coach authorised the edit): the `ifPresent` entries replaced by the Coach's text and table; nothing else touched.
  * Tests: `models-shapes.test.ts` (`'replace'` accepted, others refused, `sendOpts`), `box.test.ts` (send: with and without `ifPresent: 'replace'`, a box believed never stored refuses `stale_write` over a stored live box and over a stored tombstone, the call log showing `expected` null and the store unchanged; nothing stored lands at the minted seq 0; timely options; `'fetch'` refuses `bad_option` before staging), `listing.test.ts` (the fake refuses `stale_write` for `expected` null over a live box and over a tombstone, keeps a record as given over no row; the scope guard; the staged `vault_tok` guard).
* **Decisions taken**:
  * `send` with `ifPresent: 'replace'` meets a never-stored box the same as without it, so the tests give `maxMillisSinceRefresh: Infinity` and `maxWorldMillis: Infinity` (the default edit hydrates first, and the fetch teaches the box what storage holds, so `expected` would then be given).
  * `ifPresent` is parsed and dropped in `send` as `_ifPresent` in the destructure: the checker still owns the refusal, and the value has no consumer.
* **Reworked away** (the Coach's ruling): c4f80a21's seq + 1 landing (`landed` in the fake, the `Store`/`IfPresent`/`listing.put`/`send` doc clauses about renumbering) and the overwrite tests (the replace describe in `box.test.ts`, the fake-over-any-record test and the `ifPresent`-passing test in `listing.test.ts`), and the first build's third argument to `Store.put`. Tests that relied on putting over a stored tombstone with `expected` null: none beyond this thread's own (the one made for the overwrite, replaced by the refusal test); the whole suite was green with the fake's stricter rule without a seed change.
* **Deviations**: none. `cacheable`/`ToCacheable` untouched (the Coach has not ruled).
* **Discoveries**: the scope guard overlaps `#demandRecordOfScope` (record against the answer's scope) from #383; together they pin answer scope = scope asked = record scope. A changeset is empty (`--empty`): `ifPresent` is accepted and changes nothing a host sees beyond a refused value.
