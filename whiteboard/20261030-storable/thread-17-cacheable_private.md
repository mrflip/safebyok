# Thread 17: `cacheable` private (2026-10-31)

Branch `20261031-cacheable_private`, PR #389, stacked on #388. Justify: green (safebyok 4328 passed, 37 skipped; every package green, size budgets unmoved).

* **Built**:
  * **`ToCacheable` and the `cacheableOf` helper are gone.** The storable's `settle()` now makes the copy for the device cache (central and staged beside the sparse form) from its private `#central` and `#staged`, and pushes it into `listing[MSX.KeepCopy](cacheable)`, a new method of `Listing` keyed by a module-private symbol (`src/models/listing.ts`, banner *Snapshot and subscription*). The listing holds the latest copy per scopepath in `#copies`. `#buildOrReceive` then calls `this.settle(scope)`, which saves the copy kept for that scope (`#cache.save`) and remakes the snapshot, as `settle(thing)` did. The listing's `settle` argument changed from a thing to a scope.
  * **Nothing reads the copy off an instance.** `receive` and `settle` still return `{ badnews }` only; no symbol, no `cacheable` getter. A test (end of `listing.test.ts`, *The copy an instance hands in*) says so.
  * **Behaviour unchanged**: the cache is saved on each delivery and each build, never on `hello`'s revive, never on an edit. An edit, a `send` and a revive do hand the listing a copy (`[KeepCopy]` runs at every `settle`), which is kept and not saved.
  * **Test world** (`tests/test-helpers/models-world.ts`): `mw.kept` (a map by boxlabel of the copies handed to `[KeepCopy]`; the listings `boxListingOf` and `fakeSealBoxListingOf` make log into it through a private `KeptBoxListing` subclass); `keptOf(mw, box)` replaces `cacheableOf(box)`, and `lastSaveOf(mw, box)` gives what the fake cache last saved for the scope. The 147 references became `keptOf(held.mw, box)`, one mechanical substitution; the suite passed unchanged.
  * **Four tests appended** to `listing.test.ts`: an edit hands a copy and saves none; the delivery's saved copy is left behind by a later edit; a revive hands a copy and saves none; no instance carries a way to the copy.
  * **The trivial fix** from thread 16's review, its own commit: titles asserting a null `priorTok` now say "sends no prior tok ..." (`box-listing.test.ts` 65; `listing.test.ts` 151, 160, and 230, a fourth of the same pattern the brief did not name).
* **Decisions taken**:
  * **A push by `keepCopy` at every `settle`, the save at the delivery.** The brief's "settle hands its cacheable to the listing's save" cannot be a save at every settle: `settle` runs at an edit, a `send`, and the constructor of a revived instance, and the cache is saved at none of those today. So `settle` hands the copy in, and the listing, which knows a delivery from a revive, decides when to save it.
  * **Tests read the pushed copy, not the saved one.** The Coach suggested asserting on the fake cache's saves, the snapshot or what was put. Most of the 147 references read central or staged after a direct `box.receive`, an edit or a failed `send`, none of which saves; the snapshot does not show central (nor the staged tombstone), and a `put` shows the staged only when it is sent. `keptOf` reads what the storable pushed, which follows its state at each `settle`, and is the push seam's own observable. Where a test is about the cache, it compares `callsOf('save')` to `keptOf` (the save is the copy kept). `lastSaveOf` is there for new tests that need the saved copy.
* **Approaches set aside**:
  * Returning the copy in `Settled` from `settle`/`receive`: a public method of a box a host holds would hand over the staged record (the leak `ToCacheable`'s symbol was made to avoid); and a `receive` that adopts nothing would still need to return one.
  * `settle` saving at every call through `[KeepCopy]`: changes behaviour (saves at edits, at a revive).
  * A getter `cacheable` made `protected`: the listing could not call it.
* **Deviations**: none now; see *Rework*. (First built with a public `Listing.keepCopy`.)
* **Discoveries**: `#copies` keeps one entry per instance made (the latest copy, sharing the records `#things` already holds). Nothing is ever removed from `#things` either.
* **For the Coach**: whether tests reading `keptOf` is the reading of "assert instead on what the fake cache saved, on the snapshot, or on what was put" you meant, or whether those that read central and staged mid-life should be rebuilt around saves (which means a delivery in each test that has none now).

## Rework (review of PR #389)

* **`keepCopy` is off the public surface.** A public `Listing.keepCopy` was a typed write door into the next cache save (`box.listing.keepCopy(forged)`, saved by a delivery that adopts nothing). The method is now `[KeepCopy]`, keyed by `MSX.KeepCopy`, a unique symbol declared in `models-shapes.ts` beside `IsListing` and `ToCacheable`'s old place; defined on `Listing`, called from `Storable#settle` as `this.listing[MSX.KeepCopy](...)`, overridden in the test world's `KeptBoxListing`. The push stays a push. No validator on it: thread 18 decides that. Set aside: a `protected` method (the storable could not call it), and a closure handed to the storable at construction (more machinery than a symbol, which the code already uses for `IsListing`).
* **The settle-after-adopt invariant** is a comment at `Storable#adopt`: every adopt is followed by `settle`, since the listing saves the copy last pushed, not the state at save time.
* **Tests**: `keepCopy` is not a string-keyed member of a listing (own names along the chain); a delivery judged 'same' saves the current central and staged, compared with `keptOf` after an edit staged before the delivery (before, the test only counted saves).
