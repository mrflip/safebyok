|  | drafting | **G492** Recovery keys: a second high-entropy envelope, waiting on the host's UX (show once, warn, use flow) — NOT YET. A recovery key would be one more way into a vault: a high-entropy code the user keeps, held as its own unlock envelope in the bundle's `unlocks` list, the same mechanism as fingerprint (passkey) unlock. That list exists today and holds `passphrase` and `passkey` envelopes (`UnlockMethodVals` in `types.ts`). What keeps it NOT YET is not the crypto but the UX and microcontent the host must own: a screen that shows the code once, a warning the user reads, and a flow for using it. The library's job is the envelope; the rest is the app's. |  | drafting | **G501** `maskCarefully`: keep one or two combining marks per base character and drop orphaned marks at a cut edge — NOT YET. `mask`, in the `safebyok/utils` entry ([#37](https://github.com/mrflip/safebyok/pull/37)), shows which API key a lockbox holds by printing a little of it between stars.
