# 2026-10-21: try_forms done ([#225](https://github.com/mrflip/safebyok/pull/225)) -- three questions

Every `x` and `tryX` is a plain method of `Vault`; `tryX` holds the implementation in a
`try`/`catch` and answers `good(...)` or `#badOutcome(err)`. `getBox` returns the `Box`,
`getWhisper` the whisper, `decryptWhisper` replaces `openBox`, `useWhisper` replaces `useBox`.

1. **Calls are no longer bound.** The class doc promised every method could be handed on alone
   (`onClick={vault.lock}`, `const { unlock } = vault`), and `@typescript-eslint/unbound-method`
   enforced it by its effect on tests. Plain methods drop that: only `subscribe` and `getSnapshot`
   stay bound, for `useSyncExternalStore`. The class doc, `vault-make.test.ts` and the changeset
   say so. If the promise should stay, the way to keep it with plain methods is a constructor
   that binds them; say so.
2. `getBox` refuses `absent_box` for an empty label, so it returns `Box`, not `Box | null` as in
   `vault2.ts`. Should absence be `null` instead?
3. "getWhisper deserializes the decrypted json": `Box.tryOpen` already decrypts and parses in one
   step (`openRecord`), so I did not split it. Say if you want `Box` to expose the decrypted text.
