A `/compact` instruction decides which topics the summary keeps; these rules say how to record them.
For a topic the instruction calls unimportant, name the file or PR that has its record and keep
nothing else.

Beside what a summary already keeps:

* Give each decision its status as it stands: settled (by whom, and where it is recorded), or
  open (proposed, built but not yet reviewed, or awaiting a ruling). A plan or a proposal stays
  one in the summary; it does not become a decision.
* Where a decision still open would change what code promises its callers, quote the promise as
  it stands: the comment or test that states it.
* Keep each ruling beside the question it answered, in close to the words it was given in.
* Name the files and PRs that hold the record (plans, thread files, handoffs), so that the work
  goes on from the record rather than from the summary.
