**`Scopepath` replaces `Ckeys`.** Where a key-value store files each row is now a scope's *scopepath*, from the exported `Scopepath` namespace; `Ckeys` is gone. The strings are unchanged (`vault^acme^u1^main`, `box^acme^u1^main^openai`, `lease^…`, `device^…`), so nothing stored moves and every vault already written is found as before. A key-value adapter of your own renames its calls: `Ckeys.vaultProps(scope)` is `Scopepath.vault(scope)`; `Ckeys.box(scope, boxlabel)` is `Scopepath.box({ ...scope, boxlabel })`; `Ckeys.lease` is `Scopepath.lease`; `Ckeys.deviceRecord` is `Scopepath.device`; `Ckeys.boxPrefix` is `Scopepath.withinVaultScopepathPrefix`; `Ckeys.isBoxIn` is `Scopepath.withinVaultScopepathPred`; `Ckeys.isLease` is `Scopepath.isLease`; `Ckeys.isDeviceRecord` is `Scopepath.isDevice`; `Ckeys.Delimiter` is `Scopepath.Delimiter`. `Ckeys.boxlabelOf(row)`, which answered null for a row no box is filed under, is `Scopepath.isBox(row) ? Scopepath.boxscope(row).boxlabel : null`. New: `Scopepath.bank`, its inverse `Scopepath.bankScope`, `Scopepath.vaultScope` and `Scopepath.boxscope` (each refusing `bad_scope` for text that is not a scopepath of its kind), `Scopepath.isBox`, and the types `BankScope` and `Boxscope`.

What a host may see: each maker checks its whole scope, refusing `bad_scope` for any name that fails its check (a `label`, or a `user_id`) where `Ckeys` refused only a name holding `^`; the public verbs refused such names already, so only a host calling `Ckeys` directly with one meets it. `memoryDeviceDB` and `idbDeviceDB` refuse a scope whose names fail their checks as `bad_scope`, alike. `idbDeviceDB`'s sweep of rows this version did not file now also deletes a lease or device record filed under a malformed scopepath (`lease^acme^u1^Main`), which no read could ever reach. `localVaultDB` and `idbVaultDB` list a vault's boxes as before, passing over a row under the vault's prefix that is no box's scopepath rather than failing the read, and erase it with the vault.
