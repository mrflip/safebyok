**Refusals say less: no refusal repeats a key or a value it was handed.** A field an object does not take is counted, never named, and the refusal lists the fields the object takes: `hello({ staleMinute: 0 })` is refused "There is a field it does not take (its name is not repeated): it takes only staleMinutes. Check the spelling, or leave it out. hello()'s only option is ...", where it said "There is no field staleMinute". What changed, for a host reading messages:

* `Bank.make` refuses an option it does not take as any strict bag does, prefixed "In Bank.make's options:". It no longer names an option's new name (`forcePassphraseReentryHours`, `passphraseStrengthTest`) or says that a `vaultlabel` goes to `bank.ensureVault`; its list of the options it takes says it. A refusal of an option's value reads "In Bank.make's options: leaseHours: ..." where it read "Bank.make's leaseHours: ...".
* The bag naming a vault (`bank.ensureVault({ vaultlabel })` and the rest) is read for its scope alone: a `vaultDB`, `deviceDB` or `vaultDb` in it is left out, as any other field is, where it was refused 'bad_option'. A vault's own stores go in the second bag, as before.
* `hello()` and `ensureUnlocked()` say how to wrap them as an event handler in every refusal of their options, where they said it only for something that was not a plain object.
* `parseKeyDeriverSpec` (and `argon2idDeriver`) refuse a spec Argon2id cannot run in one sentence saying what each field must be, where they named the failing field.
* `Wayin.make` refuses a record this package never writes as the schema's own 'bad_record', where it refused 'damaged_wayin' with the 'bad_record' as its cause. A vault's damaged wayin, met on unlock, is still 'damaged_wayin'.
* A sidecar that is not plain JSON is refused whole, "An object in a whisper or a sidecar is a plain object of JSON ...", naming none of its keys.

**Stored format:** unchanged.
