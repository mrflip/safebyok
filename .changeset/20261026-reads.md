**Exports: the last "props" names are "record" names.** A VaultDB's `putVaultProps` is `putVaultRecord`, and the half an adapter writes `doPutVaultRecord` (it replaces the vault record alone, as `putBox` replaces one box record; `putVault` would promise the boxes too). A stale update's refusal carries what stands as `meta.vault_stored`, beside a box write's `meta.box_stored`, where it was `meta.vault_props_stored`: a host that reads it renames the field. `Refusals.staleVaultProps` is `Refusals.staleVaultRecord`, and `Expectations.vaultPropsPutOf` and `Expectations.vaultPropsRefusalOf` are `Expectations.vaultRecordPutOf` and `Expectations.vaultRecordRefusalOf`. Convex's component and host function `putVaultProps` is `putVaultRecord` (its answer validator `PutVaultRecordAnswer`), and GraphQL's mutation `safebyokPutVaultProps` is `safebyokPutVaultRecord`, answering `vault_stored`: a host deploys the new Convex functions or GraphQL schema with this release.

**Exports: a vault read answers its record and its boxes, sound and damaged apart.** A VaultDB's `getVault`, `ensureVault`, `getVaultRecords` and `ensureVaultRecords` resolve the vault record with `boxes` and `damagedBoxes` beside its fields (`val.vault_tok`, `val.boxes`, `val.damagedBoxes`), frozen, where they resolved `{ vaultProps, boxes }`; `getVaultRecords` now hands on what `getVault` does, checked and split. `boxes` holds each sound box as its `BoxSparse` (every field of its record but the two ciphered ones, `format` and the codec among them); `damagedBoxes` holds each box whose record does not read back as a `BoxDamaged`, `{ boxlabel, revision_tok, damage }`, where `damage` is `'damaged'`, or `'newer_format'` for a record a newer safebyok may have written. A damaged box is never among `boxes`: a host that branched on `box.damaged` reads `damagedBoxes` instead, and offers update-the-app, not deletion, for `newer_format`. `BoxSummary`, `ListedSummary`, `DamagedBox`, `BoxVisible`, `StoredVault`, `ListedVault` and `VaultRecords` are gone; `BoxSparse`, `BoxDamaged`, `BoxDamageVals`, `DamagedBoxRecord`, `DamagedVaultRecord`, `VaultReadResponse` and `splitStoredBoxes` are new. A stale box write's `meta.box_stored` and a `damaged_box` news's `meta.box_listed` carry a `BoxDamaged` for a damaged box.

**The snapshot** gains `damagedBoxes` beside `boxes` (and the Vault object a `damagedBoxes` getter); `boxes` holds sound boxes alone, each a `BoxSparse`, without the `vault_tok` and `damaged: false` a `BoxSummary` carried. A damaged box still holds room in `capacity`.

**Storage adapters.** `doGetVault` and `doEnsureVault` resolve a `VaultReadResponse`, `{ vault, boxes, damagedBoxes }`: the vault record exactly as stored (or a tombstone, or null), and the box rows handed to `splitStoredBoxes` as `StoredBox`es, which judges each, so an adapter adds one line: `return { vault: row ?? null, ...splitStoredBoxes(rows) }`. The base class checks every answer again: the vault record as before, each sound box as the split judges a row, and each damaged box's boxlabel, revision and damage, refusing a malformed one as `corrupt_record`. `safebyok-indexeddb`, `safebyok-postgres` and `safebyok-convex` split their rows so. `safebyok-convex`'s component answers `{ vault, boxes }` where it answered `{ vaultProps, boxes }`, and its `putVaultRecord` takes `vaultRecord` where `putVaultProps` took `vaultProps`. `safebyok-graphql`'s `SafebyokVault` is `{ vault, boxes: [SafebyokBoxSparse!]!, damagedBoxes: [SafebyokBoxDamaged!]! }` (`SafebyokListedBox` is `SafebyokBoxSparse`), the server's resolvers relay the split, and the browser's VaultDB passes it through, dropping `__typename`; `safebyokPutVaultRecord` takes `vaultRecord`. The Postgres README's route recipe relays the split the same way (`relayed`): redeploy the route, the Convex functions or the GraphQL schema with the app.

**Stored format:** unchanged. A box in a `format` this version does not know now lists as `newer_format` rather than plain damaged.
