Stored records are unchanged: every vault and box already written reads as before. **The box record schema `Box` is now `BoxRecord`**, the type and the Zod schema alike, in the core and in every storage adapter's signatures (`doPutBox(scope, box: BoxRecord, expected)`); the Convex component's mirror validator is `BoxRecord` too. A custom VaultDB or route that imported `Box` imports `BoxRecord`. **`Box` is now a class**, the box as the vault holds it: `Box.make(vault, record, vaultProps)` checks a record (`bad_record` otherwise) and keeps it, frozen, as `box.props`, under the vault props it lies in; every stored field is a field of the box, `sidecar` as its parsed JSON value; `box.summary` is what `vault.boxes` lists; `JSON.stringify(box)` writes the record, never its vault. `Box.seal(vault, boxlabel, whisper, vaultProps, vaultKey, { sidecar, over })` seals a whisper under a fresh boxKey, and `box.tryOpen(vaultKey)` / `box.open(vaultKey)` open one. **New on the vault**: `vault.openBox(box)` and `vault.tryOpenBox(box)` open a `Box` or a `BoxRecord` with the key in hand, reading no storage and asking for no proof (`vault_locked` otherwise); read-only `vault.logger`, `vault.clock` (checked: a clock that fails locks the vault) and `vault.keyDeriver`. `vault.boxes` entries, their sidecars included, are now frozen through: code that changed a listed sidecar in place now throws in strict mode. `meta.box_stored` is typed `BoxRecord | null`. **`safebyok/utils`** exports `adorn` and `decorate`, which attach a hidden, fixed property to an object. New types: `BoxHolder`, `BoxVault`, `SealBoxOpts`. A `putBox` whose kept sidecar takes it past `maxWhisperBytes` is refused before anything is sealed.
