**Every VaultDB verb resolves an `Outcome` instead of throwing, and `VaultError` gains `family` and `meta`.** Stored records are unchanged: every vault already written reads as before.

A storage adapter's public verbs -- `getVaultProps`, `ensureVaultProps`, `putVaultProps`, `delVault`, `delDamagedVault`, `listBoxes`, `listBoxRecords`, `getBox`, `putBox`, `delBox`, on `localVaultDB`, `idbVaultDB`, `postgresVaultDB`, `convexVaultDB`, `graphqlVaultDB` and any adapter built on `VaultDB` -- now resolve `{ ok: true, val }` or `{ ok: false, err }`, and never reject: `err` is the `VaultError` the verb used to throw. Code that calls a VaultDB directly reads `val` (`const { ok, val, err } = await vaultDB.getBox(scope, boxlabel); if (! ok) { throw err }`). An adapter's own `do*` methods are unchanged, and still refuse by throwing. A VaultDB that wraps another VaultDB's verbs inside its `do*` methods must unwrap them: their answers are Outcomes now, and an Outcome handed up as a record reads as damaged. The vault's own calls (`vault.getBox`, `vault.putBox`, `hello`, `unlock` and the rest) still throw, as before. A host that copied the `safebyok-postgres` README's route recipe updates its POST handler as the README now shows, reading the Outcome each verb resolves.

`VaultError` gains `family`, read from its `refusalkind`: `misuse`, `condition`, or the new `bad_news` -- `damaged_vault`, `damaged_wayin`, `damaged_box`, `newer_format`, `rolled_back` and `identity_revoked`, which were conditions. `isVaultCondition(err)` is true for both `condition` and `bad_news`, so it answers as before. `VaultError` takes `{ cause, meta }`, and `meta` names what a refusal learned (`box_stored`, `vault_props_stored`, `capacity`); no refusal fills it yet.

| Was | Now |
| --- | --- |
| `VaultErrorKind`, `VaultErrorKindVals` | `RefusalKind`, `RefusalKindVals` |
| `VaultErrorFamily`, `VaultErrorFamilyVals` (`misuse`, `condition`) | `RefusalFamily`, `RefusalFamilyVals` (`misuse`, `condition`, `bad_news`) |
| `VaultErrorFamilyForKind` | `RefusalFamilyForKind` |
| VaultDB verbs resolving their answer, rejecting with a `VaultError` | resolving `Outcome<answer>` |

New exports from `safebyok`: `outcomeOf(thunk)`, which runs a body that throws and resolves its `Outcome` (a thrown error that is no `VaultError` becomes `storage_unavailable`, the error as its `cause`); the types `Outcome`, `GoodOutcome`, `BadOutcome`, `RefusalMeta`, `VaultErrorOpts` and `Capacity`. From `safebyok/testing`: `expectGood`, `expectBad`, `expectingGood`, `good` and `bad`.
