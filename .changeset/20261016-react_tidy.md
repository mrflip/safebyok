`safebyok-react`'s passphrase dialog is a modal `dialog` with Escape to cancel, an always-mounted live region for its error line, and the passkey offered first; it follows the vault's snapshot as it changes and starts afresh when handed another vault. `VaultProvider` ties each dialog to the vault the refused action ran against, runs an action refused just as the vault unlocked again without a dialog, warns once when a `logger` or `clock` prop changes identity, and takes `allowStartOver`, which lets a user who forgot the passphrase erase the vault and start a new one. Its `eraseDamagedVault` now opens again only on `stale_write`, and rejects `bad_option` without reopening. `PasskeyUnlockButton`'s `onGripe` now also hears `null` as each press begins (a host typing it `(gripe: string) => void` widens it to `string | null`), and it takes `autoFocus`. New: `WhisperField`, a hidden-as-you-type field for a whisper with Show / Hide. The dialog's window line is left out on an engine without `Intl.RelativeTimeFormat` (the README names the polyfill), and a window within a minute of `ForeverMs` reads "until you lock it". In `safebyok`: `WhisperFieldAttributes` (from `safebyok/utils`), the attributes that ask password managers to leave a whisper field alone, and `parseLogger`, the logger a vault keeps, for a binding with something of its own to say.
