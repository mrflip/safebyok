**A VaultDB reads a vault whole, and vault props may be gateless.** `VaultDB.getVault(scope)` and `VaultDB.ensureVault(scope, draft)` resolve `{ vaultProps, boxes }`, the vault props and the box listing read in one atomic step (one statement in Postgres, one query or mutation in Convex and over GraphQL, one IndexedDB transaction), `ensureVault` creating the vault from a gateless draft where none stands (VAULTDB.md, lines 2.4 and 3.1). `getVaultRecords` and `ensureVaultRecords` read the same with the boxes as stored, for a server to serve a browser's VaultDB. `VaultProps` is now `GatedVaultProps` (`gate_epoch` 1 or more, a passphrase) or `GatelessVaultProps` (`gate_epoch` 0, `passphrase` and `passkey` null), under the same `safebyok-vault-v6`: every record written before reads as it did. `putVaultProps` takes an expectation at `gate_epoch` 0, and its `stale_write` carries the vault props standing as `err.meta.vault_props_stored` (null for none); `Refusals.staleVaultProps(standing)` and `Expectations.vaultPropsRefusalOf` make it, and `Refusals.staleWrite('vaultProps')` is gone. The vault still reads through `getVaultProps` and `listBoxes`, and reads gateless vault props as no vault yet. **An adapter of your own** implements `doGetVault` and `doEnsureVault`, each from one atomic step, and throws `Refusals.staleVaultProps(standing)` from `doPutVaultProps` when it misses: a `false` now refuses as `corrupt_record`. **Convex** hosts re-export `getVault` and `ensureVault` from `convex/safebyok.ts` beside the others (`convexVaultDB` refuses an `api` without them) and deploy the component, whose vault props take a null passphrase and whose `putVaultProps` answers `{ landed }`. **Postgres** hosts with tables already made run `ALTER TABLE safebyok_vaults ALTER COLUMN passphrase DROP NOT NULL`, as `VaultTablesSql` never changes a table already there; until then a gateless vault cannot be stored. **A GraphQL** server deploys its new schema with its clients (`safebyokGetVault`, `safebyokEnsureVault`, `SafebyokVault`, and a nullable `passphrase`), and a `ServedVaultDB` of its own adds `getVaultRecords` and `ensureVaultRecords`.
