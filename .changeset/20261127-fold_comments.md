None: safebyok is private at 0.0.0. Comments, doc blocks, STYLE.md, VOCABULARY.md and the names below, and two phrase texts a host may read: `VaultDBExpected` no longer mentions builders, which a VaultDB has none of, and `DeviceDBExpected` names `ensureDevicetok` beside `peekLease`, `stowLease` and `listen`.

Some names change too, and everything answers as before. For an adapter author: the datastore's row as it stood before a write or a stow is `prior`, beside `proposed` and `actual`, where it was `ante`. `AnteWayins` (from `safebyok/storage`) is `PriorWayins`; the second parameter of `ManifestTags.writeTagsOf`, `birthTagsOf`, `policiesOf`, `isWritable` and `isBirthWritable` is named `prior`. A lease is made of its record, the bank it is attached to and the life of the gate it is used under: `Lease.make(record, { bank, gateLife })`, where it was `{ gate }`. `LeaseGate` (from `safebyok/core`) is `LeaseBank`, which a `Bank` is: it has no `gateLife`, and reads `device.leaseMillis` where it read `leaseMillis`. In safebyok-postgres's `VaultFunctionsSql`, the write statements' alias `ante` is `prior`, and the parameters `ante`, `ante_lifeseq`, `ante_am`, `ante_lifepath`, `ante_wayins`, `ante_gate` and `ante_root` of `lifeseq_ok`, `lifepath_kept`, `presence_of`, `revtok_cmp_of`, the three `*_refusal` functions, `policy_verdict_of`, `policies_of`, `write_tags_of` and `birth_tags_of` are `prior`, `prior_lifeseq` and so on. Postgres will not rename a function's parameter in place, so a host that runs `VaultFunctionsSql` over functions it installed before first drops those eleven, as it does for any function whose arguments changed.
