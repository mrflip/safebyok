**`IdbDeviceDB` and `idbDeviceDB(opts)` on `safebyok/browser`: the device store a browser app hands `Bank.make`,** keeping each lease in IndexedDB under the database `${dbName}:device-v1` (`dbName` defaults to `safebyok`), its leaseKey kept as a handle by structured clone, never as bytes. On its first call it deletes the old device databases unread, `${dbName}:device_db` and any earlier `device-v<N>`: a lease cached by an earlier build is gone, and the next session proves again; a tab of an older build still holding one open keeps it until that tab closes. The core now depends on `idb-keyval`. **`DeviceDB` gains `listRawLeases()` and `tryListRawLeases()`,** every stored lease row as a bag, unchecked, damaged rows among them, which `listLeases` leaves out. **A lease is cached by `lease.cache()`, `lease.tryCache()` and `lease.cacheAsCacheCan()`**, where `stow`, `tryStow` and `stowAsStowCan` were; the deviceDB keeps `stow`, `peek`, `forget` and `listLeases`. **`safebyok/storage` exports `inOneStep` and `rowAt`,** the one IndexedDB transaction both the core's store and safebyok-indexeddb's use. safebyok is not yet released, so none of this keeps a compatibility layer.
