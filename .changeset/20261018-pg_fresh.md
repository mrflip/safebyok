The Postgres schema is one definition, made fresh: `VaultTablesSql` creates `safebyok_vaults` and `safebyok_lockboxes` whole, and `VaultNotifySql` the one trigger function and its two triggers, with no upgrade step anywhere; this release's entries no longer give `ALTER` or rename steps, and a database made before it drops the tables and runs them again, as this release's entry "The vocabulary reform, in one place" says. `safebyok_vaults` now lists `vault_id` before `format`, so both tables open with the vault's scope and `vault_id`, then `format`. The README says why push needs a trigger, and that `VaultTablesSql` never changes the columns or keys of a table already there.
