A lockbox's public bag is now its sidecar: your app's own plain data, riding beside the whisper, authenticated but not encrypted. Exports: PublicBag is Sidecar; store()'s only option, public, is sidecar (store(boxlabel, whisper, { sidecar })); and a lockbox summary's public is its sidecar, in the snapshot and in a VaultDB's listing. Stored: the lockbox's format is safebyok-lockbox-v5 and its public_json is sidecar_json, and both are bound into the lockbox's encryption. The Postgres column public_json is sidecar_json: VaultTablesSql creates only what is missing, so an existing database runs ALTER TABLE safebyok_lockboxes RENAME COLUMN public_json TO sidecar_json. The GraphQL schema's lockbox field public_json is sidecar_json, so a server serving it follows. The Convex component's validators follow the new field and format, so a deployment holding lockboxes written before this no longer matches the component's schema: clear the component's tables before deploying it. There is no migration: where an adapter reads a lockbox stored before this release, it lists as damaged (damaged_lockbox on read), to be erased with erase() or written over with store(), its whisper stored again.
