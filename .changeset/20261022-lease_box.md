**`putBox` takes the box first and the whisper second, and either may be left out: `vault.putBox({ boxlabel, sidecar? }, whisper?)`.** It resolves the `Box` as stored. Given both the sidecar and the whisper, it reads nothing and writes over the revision the snapshot lists (keeping its `registered_at`), or as a new box when none is listed; a listing a moment stale refuses `stale_write`. Leave either out to keep the box's own: it reads the box, opens it, and writes over the revision it read; leaving out the whisper where no box stands refuses the new kind **`no_whisper`**, at once and asking nobody for a box a locked vault's listing does not show. `putBox('label', whisper, { sidecar })` is gone: write `putBox({ boxlabel: 'label', sidecar }, whisper)`. **`getBox()` and `getWhisper()` resolve null for a box that is not there** (they refused `absent_box`); `useWhisper()` and `delBox()` still refuse `absent_box`. **`delBox()` resolves what it removed**, `{ boxlabel, vault_tok, outcome: 'deleted' | 'deleted_other' }` (the exported `DeletedBox`). **`vault.decryptWhisper(box)` is gone: a `Box` opens itself with `box.extractWhisper()`** (and `tryExtractWhisper()`), under the vault's lease, which is now public as `vault.lease`; a `Lease` hands out no record (its `record` getter is gone), so nothing reachable from a Vault object yields a key or a wrapped key. **`vault.tryDemandConsistentWith` is gone**: `vault.consistentWith(thing, { leaseBound? })` asks the demand's question as a boolean, refusing nothing and dropping no lease, beside `demandConsistentWith`, which throws. A `Box` carries the whole stamp of the vault it was made under (`applabel`, `user_id`, `vaultlabel`, `vault_tok`, `vault_epoch`, `gate_epoch`), shown in `{ ...box }` and its JSON, and refuses `vault_gone`, `vault_remade` or `gate_moved` once the vault moves on; a box sealed and not yet stored names the revision it was sealed over as `box.baseRevisionTok`. `Box.seal(vault, { boxlabel, sidecar?, base? }, whisper)` (with `Box.trySeal`) seals under the vault's lease; `box.tryOpen` and `box.open` are gone. **A `Lease` no longer holds the vaultKey unwrapped**: `lease.cipheredWith(bytes, visible)`, `lease.decipherWith(ciphered, visible)` and `lease.sealProps(visible, { whisper })` (each with its `try` form) unwrap it for that one call; `Lease.grant`, `lease.tryOpen`, `wrapBoxKey` and `unwrapBoxKey` are gone. A lease this device keeps is taken up as read, and one whose wrap will not open refuses its first use with the new kind **`damaged_lease`** (bad news), erasing it and locking the vault, where it was discarded at the hello with a warning. A lock landing while a `putBox()` seals its whisper now refuses `vault_locked`, writing nothing; one landing while `getBox()` reads lets the box through, as it holds nothing secret. **`VaultDB.getBox(scope, boxlabel, expected)` takes the `vault_tok` its reader holds** (`BoxGetExpectation`) and refuses `vault_mismatch`, reading the vault props and the box in one step, where that vault no longer stands; every adapter does so (the Convex component's `getBox` query answers `{ read, box_stored }` or `{ read: false, refusalkind }`, the GraphQL `safebyokGetBox` field takes `expected`, Postgres reads both in one statement). A vault's box read that meets it refuses **`vault_gone`** (a box of a vault made anew elsewhere was `damaged_box`), and the next `hello()` reads storage afresh. **Vaults stored before** read as they did: nothing stored changes shape. A host whose own VaultDB adapter implements `doGetBox` must take the new `expected` argument and compare it in the same step as the read.
