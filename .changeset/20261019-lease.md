Stored records are unchanged: a lease already on a device is taken up as before. **`DeviceDB`'s verbs now resolve an `Outcome`**, as a VaultDB's do: `getLease` and `getMark` resolve `{ ok: true, val }`, the record or null, and the writes and erases `{ ok: true, val: undefined }`; a failure is `{ ok: false, err }`, never a rejection. `memoryDeviceDB` and `idbDeviceDB` answer so (an IndexedDB failure is `storage_blocked` or `storage_unavailable`, the browser's error its cause). A device store of your own returns Outcomes now: **wrap each verb's body in the newly exported `deviceOutcomeOf(verb, body)`**, which says your store's throw as the vault's condition -- a browser's `SecurityError`, `QuotaExceededError` or `NotSupportedError` as `storage_blocked`, anything else as `storage_unavailable`, the throw as `cause` -- where a plain `outcomeOf` would say every one as `storage_unavailable`. The vault still says a throw from one as a condition, and refuses an answer that is no Outcome as `bad_option`. `describeDeviceDB` takes an optional third argument, a factory for your adapter over a store the browser withholds, and checks each verb then resolves `storage_blocked` and never rejects. Code that read `await deviceDB.getLease(scope)` reads `valOf(await deviceDB.getLease(scope))`, as the README's rolled-back recipe now does with `delMark`. **The lease record schema `Lease` is now `LeaseRecord`**, the type and the Zod schema alike. **`Lease` is now a class**, the lease as the vault holds it: `Lease.make(vault, record)` checks a record (`corrupt_record` for one this package does not write, or another vault's) and keeps it, frozen, as `lease.props`; `Lease.grant(vault, vaultProps, vaultKeyPair, askPassphraseAt)` wraps the vaultKey under a fresh non-extractable leaseKey and writes nothing; `lease.tryOpen(vaultProps)` hands back the vaultKey while the lease fits (`vault_locked` when it has ended or the vault props moved on, `corrupt_record` when it will not open); `lease.endsWithin(millis)`. New types: `LeaseHolder`, `LeaseVault`, `DeviceVerb`.
