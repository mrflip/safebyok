**Renamed:** the type `VaultReadResponse`, what an adapter's `doGetVault` and `doEnsureVault` answer (`{ vault, boxes, damagedBoxes }`, the vault record exactly as stored beside its box rows split), is `StoredVault`. An adapter written in TypeScript changes the one word in its two signatures; nothing else of it changes.

**New:** `storageTroubleOf(thrown)`, the line every `VaultDB` verb applies to what its adapter's `do*` hook threw: a `VaultError` as it came, anything else `storage_unavailable` with `thrown` as its cause. For a server or an adapter relaying a VaultDB's throw onward.

**`safebyok-graphql`:** what a `vaultDBFor` throws passes through to the browser. Every `VaultError` it throws crosses as it is, kind and message (was: only `not_permitted` and `identity_revoked`; any other kind crossed as `bad_option` with a message saying the server's setup is wrong). Anything else it throws crosses as `unexpected_error` whose message carries the thrown error's own message (was safebyok's fixed sentence), so a server's diagnostic reaches the browser developer. What was thrown still stays on the server as the GraphQL error's `cause`, never on the wire. The browser's `graphqlVaultDB` throws each as that `VaultError`.
