**Renamed:** the type `VaultReadResponse`, what an adapter's `doGetVault` and `doEnsureVault` answer (`{ vault, boxes, damagedBoxes }`, the vault record exactly as stored beside its box rows split), is `StoredVault`. An adapter written in TypeScript changes the one word in its two signatures; nothing else of it changes.

**New:** `asStorageTrouble(thrown)`, the line every `VaultDB` verb applies to what its adapter's `do*` hook threw: a `VaultError` as it came, anything else `storage_unavailable` with `thrown` as its cause. For a server or an adapter relaying a VaultDB's throw onward.

**`safebyok-graphql`:** a `vaultDBFor` that throws anything but a `not_permitted` or `identity_revoked` refusal now crosses to the browser as `unexpected_error` (was `bad_option`, with a message saying the server's setup is wrong). What it threw still stays on the server as the GraphQL error's `cause`; the message the browser sees is safebyok's own, naming nothing of the server. A host branching on `bad_option` from a misconfigured server branches on `unexpected_error` now; the browser's `graphqlVaultDB` throws it as that `VaultError`.
