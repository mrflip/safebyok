**Renamed:** `isVaultCondition(err)` is `isCondition(err)`, in `safebyok` and as `safebyok-react` uses it; it answers as before.

**`staleMinutes` defaults to 5** (was 1): with neither `Vault.make` nor the call saying otherwise, a `hello()` within five minutes of the vault's last read of storage reads nothing anew. `StaleMinutes` is 5. A host that wants the old pace passes `staleMinutes: 1`.

**Renamed:** `ensureLease`'s and `tryEnsureLease`'s option `renewWithin` is `renewMinutes`, its unit in its name: `vault.ensureLease({ renewMinutes: 60 })` asks now if the lease ends within the hour. `renewWithin` is refused as `bad_option`, as any misspelt option is.

**One test for a refusal, across copies of safebyok.** `isVaultError(err, refusalkind?)` is true for a `VaultError` made by another copy of safebyok loaded beside this one (an ESM and a CJS build side by side, each with its own class), told by a mark every `VaultError`'s constructor sets (`Symbol.for('safebyok.VaultError')`), and every place safebyok branches on a refusal uses it: such a refusal from a storage adapter or a host function is kept as it came by the `VaultDB` base (it was `storage_unavailable`), `identity_revoked` and `rolled_back` lock the vault, bad news is told to `onBadNews`, `isCondition` answers for it, and `safebyok-graphql`'s resolvers send a host's refusal as it is. An `Error` that only names itself `VaultError` and carries a `refusalkind` -- as a host's own client might rebuild one from a server's JSON -- is no longer kept as one: it is `storage_unavailable`, its message safebyok's own, the error its `cause`. `safebyok-graphql`'s and `safebyok-convex`'s clients still rebuild a real `VaultError` from their server's kind and message, on purpose: through them, the package's own server code chooses both, as before. A host testing with `instanceof VaultError` tests with `isVaultError` instead.

**A call that cannot land never prompts.** `getBox`, `getWhisper`, `useBox` and `delBox` on a locked vault refuse `bad_label` and `absent_box` before `getProof` is asked -- the name's floor and its own check, and the box listing, read from storage once more when the listing in hand shows nothing under the name, so a box another device stored meanwhile is still asked for -- as `putBox` already refused a bad label or whisper. A host that provoked `vault_locked` with a `getBox` of a box that is not there now sees `absent_box`; `ensureLease()` is the call that asks for nothing but the lease.
