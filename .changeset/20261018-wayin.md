The unlock envelope is now the wayin, everywhere. Exports: UnlockEnvelope, PassphraseEnvelope and PasskeyEnvelope are Wayin, PassphraseWayin and PasskeyWayin; UnlockSummary is WayinSummary; UnlockMethod and UnlockMethodVals are WayinKind and WayinKindVals. The snapshot's unlocks are its wayins; vault.removeUnlock() is vault.retireWayin(); the unlockId option of unlock() and changePassphrase() is wayinId; addPassphrase() and addPasskey() take { wayinlabel }, and the validators bag's unlocklabel check is wayinlabel. Refusal kinds absent_unlock, damaged_unlock, last_unlock and too_many_unlocks are absent_wayin, damaged_wayin, last_wayin and too_many_wayins. Stored: the vault record's format is safebyok-vault-v3, its unlocks list is wayins, and on each wayin method is wayinkind, unlock_id is wayin_id, unlocklabel is wayinlabel and vault_key_wrapped is vault_key_wayin_wrapped (the prior vaultKey's vault_key_wrapped is unchanged). The Postgres column unlocks is wayins: VaultTablesSql creates only what is missing, so an existing database runs ALTER TABLE safebyok_bundles RENAME COLUMN unlocks TO wayins, the GraphQL type SafebyokUnlockEnvelope is SafebyokWayin, and the Convex component's validators follow the new fields, so a deployment holding bundles written before this no longer matches the component's schema: clear the component's tables before deploying it. There is no migration: elsewhere, a vault stored before this release reads as damaged (damaged_bundle) and must be cleared with eraseDamagedVault() and made afresh, its lockboxes stored again.
