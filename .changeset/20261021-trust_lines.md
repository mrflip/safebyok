**Stored formats: `vault_key_epoch` is gone.** The vault props are format `safebyok-vault-v6`, each box `safebyok-box-v7` and each device mark `safebyok-mark-v5`, none holding a `vault_key_epoch`, and neither a way in nor a box binds one into its ctx. There is no migration before 1.0: a vault stored before this release reads as `damaged_vault` (never `newer_format`), which `delDamagedVault` clears so the user makes the vault again; a box stored before it lists as damaged; an older device mark reads as none. The snapshot's and the vault's `vault_key_epoch` are removed, `BoxSummary` and `SeenVault` lose the field, and a `BoxExpectation` is `{ vault_id, revision_tok }`: a VaultDB of your own compares only those in a box write, and the contract's line 3.8 is gone. Postgres hosts drop `safebyok_boxes` and `safebyok_vaults` and run `VaultTablesSql` again (no `vault_key_epoch` columns); Convex hosts clear the component's tables before deploying; a GraphQL server deploys its new schema (no `vault_key_epoch` on any type or input) with its clients. **The host's clock is checked once, at `Vault.make`**: one reading must be epoch milliseconds from 1981 to 2255, or make throws `bad_option`; every later reading is taken as it comes, rounded down to whole milliseconds. A later bad reading no longer drops the vaultKey or throws `bad_option`, and a clock that later throws fails the call that read it as `unexpected_error`. `vault.clock` is removed. **The vaultKey lives in one place, the `Lease`, and `Box`, `Wayin` and `Lease` take the vault they are of.** While unlocked, the vault holds an opened `Lease`, which keeps the vaultKey's non-extractable handle in a private field, and wraps and unwraps boxKeys under it (`lease.wrapBoxKey(boxKey, ctx)`, `lease.unwrapBoxKey(boxKeyWrapped, ctx)`); locking drops it. `Lease.grant(vault, standing, vaultKeyPair)` resolves a lease already opened, its deadline the vault's `leaseMillis` from `vault.now()`; `Lease.make(vault, record)` makes one not opened, and `lease.tryOpen(standing)` resolves a new, opened Lease (it reads the time from the vault). A box seals and opens under the lease: `Box.seal(vault, lease, boxlabel, whisper, opts)`, `box.tryOpen(lease)` and `box.open(lease)`, which refuse a lease not opened or ended, and a box (or `over`) of another vault than the lease's, as `vault_locked`, and a `lease` that is no Lease as `bad_option`. A box has its own `vault_id`: the lease's when sealed, and, from `Box.make(vault, record, vaultId = vault.vault_id)`, the vault props it was read under (`absent_vault` when there are none). Ways in are `Wayin.make(vault, identity, record)` and `Wayin.seal(vault, identity, proof, deviceId, vaultKey)`, `identity` the vault props they are one of (new type `VaultIdentity`: their `vault_id` and `registered_at`). Each takes a slice of the vault, new types `BoxVault`, `WayinVault` and `LeaseVault` (and `LeaseStanding`), in place of `BoxVaultProps`, `WayinVaultProps` and `LeaseVaultProps`, which are removed, with `box.vaultProps`, `wayin.vaultProps` and a passphrase way in's `keyDeriver`. **New: `vault.now()`**, the vault's clock read now, in whole epoch milliseconds. **A vault's boxlabel `validators` gate writes alone**: `getBox()`, `getWhisper()`, `useWhisper()` and `delBox()` hold a boxlabel to the floor only, so a name the host's check refuses with nothing under it is now `absent_box`, where it was `bad_label`; `putBox()` still refuses it as `bad_label`. `delBox()` reads no box before it deletes: a box another device deleted first is `absent_box`, as storage answers it, and a delete into a vault deleted elsewhere and not made anew is now `stale_write`, as its doc block said, where it was `absent_box`.
