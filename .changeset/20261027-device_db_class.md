**DeviceDB is an abstract base class, as VaultDB is**, and `Bank.make` refuses ('bad_option') a `deviceDB` that does not extend it. A host's own device store becomes a subclass: in place of seven verbs each wrapped in `deviceOutcomeOf`, it implements eight `do*` methods (`doGetLease`, `doPutLease`, `doDelLease`, `doGetDeviceRecord`, `doRaiseDeviceRecord`, `doDelDeviceRecord`, `doDelAll`, `doDelUnreadable`), each handed the row's scopepath, returning the row as stored or throwing; the base class makes each Outcome, says each throw as 'storage_blocked' or 'storage_unavailable', and checks every record read back (the README's *Your own storage adapter* has a subclass to copy). `doRaiseDeviceRecord(scopepath, raisedFrom)` reads the row, hands it to `raisedFrom` and writes what it returns, in one transaction. `deviceOutcomeOf` and `raisedDeviceRecord` are no longer exported. **Every DeviceDB now discards an unreadable record the same way**: a lease or device record that fails its check reads as none and is deleted, but only while it still fails, in the transaction that deletes it, so a record written since is never lost. That fixes `idbDeviceDB` erasing a device record raised while it discarded an unreadable one. A host's own store that handed back unchecked rows saw the vault warn of an unreadable lease and leave it; such a row is now discarded without a word, and the warning comes only for a lease of another scope. `safebyok/testing` gains `spyOnDeviceHook(deviceDB, verb)`, a spy on the `do*` method behind a verb, for a test to have the store itself fail.
