A failure of the device store (a `DeviceDB`) no longer carries the store's own error as the condition's `cause`: 'storage_blocked' and 'storage_unavailable' from `getLease`, `putLease`, `delLease`, `getDeviceRecord`, `raiseDeviceRecord`, `delDeviceRecord` and `delAll` keep neither the throw nor its message, reading only its `name`, since a device store is handed every lease record and its error may quote one, and the logger hands a condition to the host whole. A host that read `err.cause` off one of these sees `undefined`; what a custom store threw is the store's own to log. A `VaultDB` adapter's 'storage_unavailable' still carries its cause, as it holds only ciphertext. The Lease and Box throwing forms (`Lease.cipheredWith`, `Lease.decipherWith`, `Lease.sealProps`, `Box.seal`, `box.extractWhisper`) now end in one catch that surfaces any throw that is no `VaultError` (a bug) as 'unexpected_error', the throw its cause, so none leaves raw; every refusal passes through unchanged. Inside them each WebCrypto call is caught alone, its ctx built beforehand, so a vault stamp that fails its check refuses 'bad_record' where it read as 'damaged_lease' (and locked the vault) or as a wrong proof; a WebCrypto failure while a box is ciphered now arrives as 'unexpected_error' without the post-wait consistency demand running first.
