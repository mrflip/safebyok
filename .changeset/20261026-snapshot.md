**Breaking: a vault's snapshot carries what a host renders, and nothing more.** `vault.snapshot` (and `getSnapshot()`) is the vault's scope, `format` and `vault_tok`, flat, beside `gate`, `boxes`, `damagedBoxes`, `capacity`, `ask_passphrase_at`, `freshness` and `trouble`. It still duck-types as a scope a bank call takes, and `vault.demandConsistentWith(snapshot)` still judges it: it checks the scope, the `vault_tok` and whether the Vault object is gone, and, with no epochs in the snapshot, no longer catches a change to the ways in (`gate_moved`). A host chooses its screen from two fields: `gate === null`, set a passphrase; `ask_passphrase_at === null`, unlock; otherwise, the boxes. What left it, and what to read instead:

* `state` is gone. `state === 'novel'` is `gate === null`; `state === 'locked'` is `gate !== null && ask_passphrase_at === null`; `state === 'unlocked'` is `ask_passphrase_at !== null`. The `VaultState` type is gone with it.
* `passphrase` and `passkey` are the gate's: `snapshot.gate?.passphrase`, `snapshot.gate?.passkey` (`gate` is a `GateSparse`, null until the first passphrase is set). Each is its wayin's sparse shape, without the `vault_tok` the summaries carried; a `damaged_wayin` refusal's `meta.wayin_listed` keeps its `WayinSummary`.
* `gate_epoch` and `registered_at` are gone: the vault's epochs are no business of a render, and `registered_at` is the Vault object's own (`vault.registered_at`).

Before:

```ts
if (snapshot.state === 'novel') { return <ChoosePassphrase /> }
if (snapshot.state === 'locked') { return <Unlock passkey={snapshot.passkey} /> }
```

After:

```ts
if (snapshot.gate === null) { return <ChoosePassphrase /> }
if (snapshot.ask_passphrase_at === null) { return <Unlock passkey={snapshot.gate.passkey} /> }
```

**Each changing part keeps its identity until it changes.** `gate`, `boxes`, `damagedBoxes` and `capacity` are each the same object until what they hold changes, across a read of storage that finds nothing new, a lock, an unlock or a change elsewhere in the snapshot: a memoized component handed one skips the others' changes. The snapshot as a whole is the same object until something in it changes, as before.

**`Box.seal` takes the box's scope and `vault_tok` from the vault it seals in.** `Box.seal(vault, props, whisper, { madeUnder, now })` reads only `vault_epoch` and `gate_epoch` from `madeUnder` (a `VaultSparse` still does); a scope or `vault_tok` there is dropped unread, so a box sealed in one vault is never made under another's name. `PassphraseProving.seal`, `PasskeyProving.seal` and a proving's `vault` are typed as the Vault object, where they took a `VaultStamp`.

**safebyok-react.** `askPasskey` takes the snapshot's gate, where it took the passkey. Before: `askPasskey(vault.snapshot.passkey)`. After: `askPasskey(vault.snapshot.gate)`. It refuses `absent_wayin`, as before, for a gate with no passkey or no gate at all. The passphrase dialog, the passkey button and the change-passphrase and passkey dialogs read the gate.

**safebyok/testing.** `TH.stateOf(snapshot)` reads `novel`, `locked` or `unlocked` from the two fields, for a test that wants all three at once; `TH.putWayin` resolves the new way in as the gate shows it.

**Stored format:** unchanged.
